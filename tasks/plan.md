# 实施计划：分布式中央认证与计量第三阶段

## 概览

在现有已验证节点身份之上实现签名中央认证、完整在线快照、短期认证租约、durable
流量批次和固定清退命令。第三阶段只做协议、代码和双节点合成验收，不部署新节点
Hysteria，不传输 TLS 身份，不开放端口或修改 DNS。

## 架构决定

- Hysteria 只调用节点回环认证代理；代理复用 Ed25519 身份访问中央面板。
- 设备上限在中央 SQLite `BEGIN IMMEDIATE` 中按新鲜快照加短租约原子判定。
- 流量先持久化节点 spool，再以 `(node_id, batch_id)` 幂等提交，提交后才 ACK。
- 远端动作只允许固定 `KICK_USERS`、`REFRESH_SNAPSHOT`、`FLUSH_TRAFFIC` 枚举。
- `protocol_ready` 与未来 DNS 入池分离；协议就绪绝不自动承载用户流量。

## 依赖顺序

签名信封与迁移
→ 在线快照
→ 中央租约
→ 回环认证代理
→ 流量 spool/结算
→ 固定命令
→ UI/合成双节点验收。

## 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 中央面板成为单点 | 新连接不可建立 | 明确 fail-closed；旧会话继续；后续再设计 HA |
| 在线/流量检查点滞后 | 跨节点超卖或配额少算 | 5 秒 freshness + 原子短租约 + 任一参与节点过期即拒绝 |
| clear 后掉电 | 极窄少计窗口 | 诚实记录限制；spool 后 at-least-once、中央 effect-once |
| 节点磁盘/队列耗尽 | 流量无法上报 | spool 大小/时间上限、告警、停止新认证且不静默删批次 |
| token 泄漏 | 用户凭据暴露 | 只在内存和签名 HTTPS 请求中存在，禁止日志/DB/审计 |
| 把协议就绪误当入池 | 用户被导向未部署节点 | 状态与 DNS admission 分离，显式管理员门禁 |

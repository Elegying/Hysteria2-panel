# 实施计划：数据节点极简对接

## 概览

把全新数据节点从“注册、激活心跳、启用协议、签发 bootstrap、部署、灰度、DNS
准入”七段人工操作收敛为一条签名命令、一次带外指纹确认和一次人工 DNS 修改。
安全门保持不变：指纹确认前不信任节点；Hysteria 身份、用户配置和 DNS 不由安装器
改动；失败必须可重试或事务回滚。

## 架构决定

- 首次命令只安装受签名固定版本、Ed25519 身份和持久 onboarding timer；后台完成器
  只有在管理员确认指纹后才能领取节点绑定的短时数据面凭据。
- 新增固定的 Ed25519 签名 bootstrap claim 合同，不增加任意命令执行面；响应丢失时
  重新签发并原子废止旧凭据。
- 自动灰度使用 bootstrap 凭据派生的短时保留身份，只允许同一节点、同一未消费 grant
  在到期前使用；不创建、修改或复用任何真实用户。
- DNS 仍由用户手工修改。面板 systemd timer 只在解析结果明确包含节点预期公网 IP、
  真实灰度通过且控制状态新鲜时自动标记准入；从不自动写 DNS，也不自动移除记录。

## 依赖图

签名 claim 合同与数据库状态
→ 节点持久完成器
→ 自动真实 Hysteria 灰度
→ DNS 只读检测与自动准入
→ 向导 UI、文档与完整质量门。

## 任务列表

### 阶段 1：自动对接合同

- [ ] 签名 claim API、幂等重新签发和协议自动启用
- [ ] 一条命令安装持久完成器并显示可人工比对的短指纹

### 检查点：注册到数据面

- [ ] 指纹确认前 claim 永远失败关闭
- [ ] SSH 断开或重启后 timer 可继续
- [ ] 成功后 FULL、UDP 443、fq/BBR、16 MiB 与证书身份均由现有事务部署

### 阶段 2：自动灰度与 DNS

- [ ] 通过临时保留身份完成中央到节点公网 IP 的真实 Hysteria 出口探测
- [ ] ACK 与灰度状态原子提交，失败不误标成功
- [ ] DNS timer 只读解析并在全部门禁满足时自动准入

### 检查点：完整用户路径

- [ ] 无真实用户数据或用户配置变化
- [ ] DNS 未包含节点 IP 时永不准入
- [ ] DNS 包含节点 IP 后无需额外点击即可准入

### 阶段 3：交付质量

- [ ] 面板向导展示“等待确认/自动部署/可添加 DNS/已准入”
- [ ] API、部署、恢复与安全边界文档同步
- [ ] 全量测试、Ruff、Bandit、Bash、ShellCheck 和差异门通过
- [ ] 五轴代码审查无剩余 P0-P2

## 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 伪造节点领取生产身份 | 全部用户身份暴露 | Ed25519、来源 IP、管理员带外指纹确认、短时 grant |
| 后台完成器变成 root 任意执行面 | 主机接管 | 固定签名版本、固定参数、root-only 文件、无服务器下发 shell |
| 自动灰度绕过用户认证 | 认证边界削弱 | 仅活动 bootstrap grant、节点绑定、短时保留用户名、ACK 后立即失效 |
| DNS 误准入 | 用户进入坏节点 | 解析 IP 精确匹配、灰度通过、心跳/快照/流量 ACK 新鲜度三门 |
| SSH 中断造成半安装 | 节点不可恢复 | systemd timer 持久重试、现有数据面事务和精确回滚 |

## 明确不做

- 不接入 Cloudflare 或云厂商 API，不保存其凭据。
- 不自动修改安全组；仅由部署和灰度失败明确暴露端口问题。
- 不轮换 Hysteria 证书，不修改域名、端口、token、HMAC、URI 或证书指纹。

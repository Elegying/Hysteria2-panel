# 实施计划：分流节点数据面第四阶段

## 概览

在 v0.26.0 的签名中央协议上增加短时 bootstrap、严格数据面安装模式和分离状态机，
先用合成节点证明秘密传输与回滚，再发布 v0.27.0，最后在 `.210` 做直连灰度。
Cloudflare DNS 入池明确不在第四阶段。

## 依赖图

bootstrap 数据模型/状态机
→ HTTPS 取件与 ACK
→ 节点配置渲染/身份验证
→ 安装器事务/systemd/回滚
→ UI 与状态
→ 本地全量质量门
→ PR/main/tag/六平台/签名 Release
→ `.201` 升级不变量
→ `.210` 部署与直连灰度
→ 第五阶段 DNS 人工门。

## 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| TLS 私钥跨机复制 | 节点失陷扩大身份暴露 | 节点/IP/签名/短时 token；无 DB/日志；节点最小权限 |
| 一键代码外泄 | 未授权取件 | 10 分钟、3 次、ACK 烧毁、只绑定已验证节点和来源 IP |
| 半安装 | 端口/文件/服务残留 | 写前快照、事务 marker、精确 owned-path 回滚 |
| 中央单点 | 新连接失败 | 明确 fail-closed；旧会话继续；本阶段不虚假宣称 HA |
| DNS 过早分流 | 用户进入未验证节点 | 第四阶段无 DNS 写路径，admission 独立字段和审批 |
| 流量 clear 掉电窗 | 极窄少计 | 延续 v0.26 已记录限制，spool 后 at-least-once/effect-once |

## 人工批准门

第五阶段再次确认。

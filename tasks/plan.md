# 实施计划：v0.14.0 可观测更新与运维控制

## 目标

在不改变任何已发放节点链接的前提下，修复在线更新“点击后没有反馈”的缺陷，补齐用户限额编辑、设备超限告警和受控重启入口，并完成两台生产服务器的升级与线路验证。

## 分阶段实施

### 1. 基线与不变量

- [x] 确认 v0.13.0 工作区、115 项测试和发布状态正常。
- [x] 核对 Hysteria `/online` 表示客户端实例数，不等同于硬件设备指纹。
- [x] 明确本轮不修改节点域名、UDP 端口、认证 token、HMAC、证书或证书指纹。

### 2. 在线更新可观测性

- [x] 为更新任务建立持久化状态和 systemd 结果判定。
- [x] 新增认证后的更新状态接口和前端轮询反馈。
- [x] 覆盖排队、运行、成功、失败、服务重启和版本未改变等路径。

### 3. 用户与系统管理

- [x] 增加单用户限额编辑弹窗，使用乐观锁且不轮换 token。
- [x] 在线客户端实例超过限制时，将用户名标红并显示文字告警。
- [x] 在系统资源模块增加受认证、CSRF 保护、固定命令的服务器重启按钮。

### 4. 质量与发布

- [x] 完成单元、HTTP、安装器合同、静态分析和安全测试。
- [x] 完成桌面端与手机端真实浏览器检查。
- [ ] 更新版本、变更日志、README、API/ADR 和校验和，发布 v0.14.0。

### 5. 生产验证

- [ ] 通过现有面板更新 155.103.116.201 和 155.103.116.243。
- [ ] 核验版本、服务、用户数据和已发放节点连续性。
- [ ] 执行 Hysteria 握手、网页、YouTube 与基础线路测试并形成报告。

## 回滚

- 每个功能按原子提交落地，可单独回退。
- 在线升级继续使用安装器的升级前快照与失败自动回滚。
- 生产升级前后不写入或替换任何节点身份材料；异常时停留在上一不可变标签。

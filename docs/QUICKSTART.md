# 从空白服务器到三节点与备份恢复

本文适用于 v0.39.13 及以后。所有地址均为示例；请替换为自己的 DNS、服务器和凭据。不要把真实密码、连接 URI、对接命令或备份上传到公开 Issue。

## 1. 规划地址和端口

| 用途 | 示例 | 要求 |
|---|---|---|
| 面板域名 | `panel.example.com` → `192.0.2.10` | 独立域名，DNS 直连面板服务器，面板 HTTPS 默认 TCP 19998 |
| 用户节点域名 | `vpn.example.com` | 指向计划承载连接的面板本机节点和/或远端节点 |
| 对接节点 | `192.0.2.11`、`192.0.2.12` | 空白受支持 Linux，root 权限，公网 IP 必须与对接填写值一致 |
| 数据入口 | UDP 19999、UDP 443 | 主端口所有启用账号可用；443 需为账号单独开启 |
| TCP 探针 | TCP 19999、TCP 443 | 仅用于兼容性探测；TCP 成功不等于 QUIC 成功 |
| 证书申请 | TCP 80 | 公网可达，用于 Let's Encrypt HTTP-01 |

支持矩阵为 Ubuntu 24.04、Debian stable、Rocky 9 的 amd64/arm64。云安全组需要自行放行；安装器只管理可确认属于项目的主机防火墙规则。面板机也是一个数据节点，不需要再次对接它。

同一个节点域名可有多个 A 记录，但 DNS 轮询不等于应用级故障切换。验收时应逐台固定连接 IP，以免只测到其中一台；节点 TLS 指纹仍使用面板发放的值。

## 2. 在面板服务器执行一行部署

用 root 登录面板服务器，执行 README 的[一行安装命令](../README.md#2-执行安装)，或使用[固定正式版验签安装](../README.md#更严格的固定版本验签安装)。

依次填写：节点名称、用户节点域名、Hysteria 端口 `19999`、面板端口 `19998`、`https`、独立面板域名、管理员账号和密码。密码输入不回显。不要把包含密码的无人值守命令保存进 shell 历史。

安装后访问 `https://panel.example.com:19998`，确认能登录且 Hysteria 已运行。在服务器上检查：

```bash
systemctl is-active hysteria2-panel hysteria2-panel-server hysteria2-panel-server-443
curl --fail --resolve panel.example.com:19998:127.0.0.1 \
  https://panel.example.com:19998/readyz
```

`ready` 表示面板、数据库和近期采集满足就绪条件，仍需进行后面的真实客户端测试。证书验证失败时核对域名、DNS、时间和证书，不能通过关闭 TLS 验证来验收。

## 3. 一键对接两台数据节点

对每台节点分别操作：

1. 在面板或 App 中打开“一键对接”，填写清楚的节点名和该机公网 IP。
2. 复制刚生成的短时签名命令，在对应空白节点以 root 执行。命令包含一次性凭据，只用于这台机器，不公开、不发送给其他人。
3. 等待自动注册、身份绑定、安装、心跳、主端口/443 真实出口验证完成。页面显示在线，并核对节点 IP 和 Agent 版本。
4. 完成这一台的实际连接测试，再接入下一台。

不需要手工确认短指纹，也不需要点击旧版的“部署数据面、灰度、DNS 准入”等多阶段按钮。DNS 由管理员提前设置，项目不会代改 DNS。

命令失效时应在面板重新生成；SSH 中断后先检查持久完成器，避免对一个正在运行的任务反复执行新命令：

```bash
systemctl status hysteria2-panel-node-onboarding.service --no-pager
journalctl -u hysteria2-panel-node-onboarding.service -n 80 --no-pager
systemctl is-active hysteria2-panel-node-auth hysteria2-panel-node-control
```

排障记录可能包含敏感命令或地址，应先脱敏。在线节点需要完整移除时使用“一键断连”；失联机器才使用“删除对接”，后者只撤销面板授权，不代表远端已卸载。重新接入已断连节点应使用新的对接命令。

## 4. 创建一个用户并逐节点验收

1. 创建专用测试用户，设置设备上限和流量额度，为双入口测试开启 UDP 443。
2. 复制连接 URI 或扫描二维码导入 Hysteria 客户端。URI 本身就是凭据。
3. 分别固定连接每台机器的主端口和 443，验证 HTTPS 目标访问、实际出口 IP、在线数和流量入账。只看 TCP 探针或 ping 不足以证明成功。
4. 检查禁用后新连接被拒绝；启用后恢复。密钥轮换后旧 URI 失效、新 URI 可用。
5. 用测试用户检查额度、设备限制、分享、二维码和本人用量查询；不要使用真实用户进行删除或清零实验。

用户流量是 `上传 + 下载`；机器展示和机器预算是两倍原始用量。机器账单和用户账不是同一个值，人工修改用户用量不会改写机器真实用量。

### 修改已用流量的时间边界

设置前会先结算面板本机已采集增量，再在同一采集锁内设置总量。远端批次使用 Agent 的秒级采样时间：人工调整当秒及以前采样、之后才送达的批次只更新机器与域名历史，不再次抬高用户人工设置值；其后的批次继续正常入账。跨越这个时间点的单个批次按采样时间整体归属，不提供逐数据包的计费切分。

节点时钟应保持同步。需要精确对齐某一业务窗口时，先断开测试用户连接并等待各节点补报结束，再设置已用值。已有“重置流量”是独立操作，会清除域名聚合并请求断开连接，不应把它与手工修正总量完全等同。

旧版面板不支持此能力时，新 App 会先提示升级，避免用“用户配置无效”误导操作者。

## 5. 一键备份与还原

在“数据迁移”下载 ZIP，放到加密磁盘或离线介质。备份包含用户、用户流量、用户名隔离信息、HMAC 和 Hysteria TLS 身份；**不包含**管理员密码、远端节点身份、机器预算/机器日账本、面板 HTTPS 私钥或 WebDAV 凭据。完整 ZIP 可以恢复用户连接身份，必须按密码级别保管。

### 原面板还原演练

只在有授权的测试环境执行：

1. 下载备份并记录测试账号身份、用量、额度、Hysteria 指纹的摘要。
2. 修改测试账号额度，或创建一个可丢弃的临时用户，作为还原前后对照。
3. 上传原 ZIP 并确认恢复；等待服务短暂维护结束，重新登录。
4. 确认备份内用户恢复、临时用户移除、管理员仍能登录、现有节点及机器预算保留。
5. 重新验证原 URI 的真实连接、双端口、流量采集和 `readyz`，确认没有未完成恢复标记。

已有对接节点时，备份 HMAC/TLS 或同名用户身份若与节点不一致，恢复会安全拒绝。不要删除事务标记绕过限制。

### 新面板迁移

新机先配置独立面板域名、安装 HTTPS 面板，再恢复用户 ZIP，验证后才接入节点和切换用户域名 DNS。目标管理员与机器配置保留；节点身份不在便携备份中，必须重新对接。原有固定端点/证书身份兼容性以恢复预检为准。

异地备份由每日 timer 调度，在 root-only 配置中提供 HTTPS WebDAV。上传临时对象后，先回读并比对 SHA-256，再原子 MOVE；正式对象再次回读成功后才记录成功并清理旧备份。未配置 WebDAV 不等于已经具备异地容灾，详见[备份与迁移](BACKUP_AND_MIGRATION.md)。

## 6. 完成标准

使用[功能验收基线](FUNCTION_ACCEPTANCE_BASELINE.md)，逐项标注“通过、失败、未测、不适用”，记录版本、时间、平台和脱敏证据。三节点验收至少应包含：三机版本和源码一致性、所有核心服务、每台双入口真实连接、账号限制、统计入账、一次备份及还原、节点断连及重新对接、故障后的状态恢复。

升级/恢复有持久事务保护，但上游增量统计清零到 journal/spool 落盘之间仍有崩溃窗口，不能承诺任意断电都零字节丢账。日常关注近期成功采集时间、spool 积压、证书有效期和最近可恢复备份，而不只关注版本号。

# 安装与升级

这份文档面向第一次部署或升级 Hysteria2-panel 的管理员。若只想快速体验，请先看项目首页的[一分钟开始](../README.md#一分钟开始)；生产环境建议完整阅读本页。

## 部署前检查

### 服务器

- 带 systemd 的 Linux，且 systemd 已运行；不支持 Alpine/OpenRC，仅安装 Bash 不能补齐服务管理能力；
- `root` 或可用的 `sudo` 权限；
- 完整的 Python 3.8 或更高版本，包含 SQLite、SSL 和 scrypt；安装器会检测并尝试补装；
- `apt`、`dnf` 或 `yum` 中至少一个可用；
- amd64 或 arm64 架构；
- 备份分区有足够空间保存升级前快照。

定期完整 E2E 覆盖 Ubuntu 24.04 LTS、Debian stable 和 Rocky Linux 9 的 amd64/arm64。其他兼容发行版属于尽力支持，生产部署前应先在同版本测试机验证。

首次下载命令需要服务器已有 `curl` 和可用的系统 CA 证书；固定版本验签入口还需要 `sha256sum` 等基础工具。进入安装器后，面板和数据节点均会按需使用系统软件源补装运行依赖，包括 Python、OpenSSL、网络检查工具和 `kmod`。已经满足要求时不会重复安装；软件源失败会停止后续部署，不会把未完成的节点标记为成功。系统软件包属于共享依赖，回滚或断连不会卸载它们。

数据节点还要求内核支持 `fq`/TCP BBR，并允许设置至少 16 MiB 的 UDP 收发缓冲；安装器会尝试加载已有的 BBR 模块。受限容器或缺少相关内核能力的主机不能仅靠安装 Python 满足这一条件。面板本机对内核 BBR 使用尽力启用策略。

小内存服务器还应检查 `free -m`、`df -h / /tmp /var/tmp` 和 `findmnt /tmp`。如果 `/tmp` 是 tmpfs/ramfs，下载文件会占用内存；当前 amd64 的 Hysteria/Cosign 暂存约 157 MiB。面板安装和升级会改用磁盘上的 `/var/tmp` 私有临时目录，退出时自动清理；如果 `/var/tmp` 也为内存盘，或不是实际目录，会明确停止并要求先检查挂载配置。复制成功后立即删除两份二进制暂存副本，再进行 HTTPS 证书依赖安装。系统依赖安装本身仍需要可用内存和磁盘；这些优化不代表任意低配置都能部署成功。

### 域名和端口

准备两个概念不同的地址：

| 名称 | 用途 | 示例 |
|---|---|---|
| `PANEL_PUBLIC_HOST` | 管理员访问面板，默认申请 Let’s Encrypt HTTPS | `panel.example.com` |
| `PUBLIC_HOST` | Hysteria 用户连接节点，可由多个节点共享 DNS | `node.example.com` |

首次 HTTPS 安装前，必须把 `PANEL_PUBLIC_HOST` 的 A/AAAA 记录指向当前服务器。公网 TCP `80` 要能被 Let’s Encrypt 访问，且不能被本机其他程序占用。

云安全组至少放行：

- 面板 TCP 端口，默认 `19998`；
- Hysteria 主端口的 UDP 和兼容 TCP 探测，默认 `19999`；
- 如需账号专属入口，放行 UDP/TCP `443`；
- HTTPS 首次签发和续期所需的 TCP `80`。

安装器可以管理已启用的 UFW 或 firewalld，但无法修改云厂商安全组。检测到不明确的自定义 nftables/iptables 策略时，安装器会停止而不是猜测规则。

## 安装方式

### 跟随稳定主线

项目首页提供可整块复制的安装命令。它先检查 Bash、systemd 和 curl，再把安装器保存成权限为 `0600` 的普通临时文件，执行后自动删除。下载失败会区分 DNS、TLS 和其他网络故障；单次下载最多等待 120 秒。这个方式把 GitHub HTTPS 和受保护的 `main/install.sh` 作为首次信任入口。

### 前置检查失败时

| 提示 | 处理方式 |
|---|---|
| 缺少 Bash / 没有运行中的 systemd | 核对系统镜像；Alpine/OpenRC 需要更换为带 systemd 的 Debian、Ubuntu 或 Rocky Linux。安装器不会自动重装系统。 |
| 下载主机或代理无法解析 | 检查 `/etc/resolv.conf` 是否存在或为有效符号链接，以及系统 DNS 服务、网络和代理配置。安装器不会覆盖解析器，也不会直接写入公共 DNS。 |
| 面板域名没有公网解析 | 核对完整域名拼写、A/AAAA 记录和本机 DNS；解析成功不代表记录指向本机或公网 TCP 80 已放行，仍需核对这两项。 |
| TLS 校验失败 | 检查系统时间、CA 证书和网络代理，不要跳过 TLS 校验。 |

进入安装器后，架构检查在依赖安装前执行；常规面板安装还会在依赖安装前检查下载主机解析（有 `getent` 和 `timeout` 时，最多 15 秒）。配置 HTTPS/ALL 代理时，目标域名可能由代理解析，因此交由实际 HTTPS 下载验证；缺少解析工具时同样由下载器报告错误。恢复和卸载路径不依赖这项网络检查，避免断网阻塞恢复。下载器遇到 curl 5/6 会清理部分文件并立即报告解析问题，其他传输错误仍有限重试。

不要改成 `curl … | bash` 或 `bash <(curl …)`。安装器需要从同一个普通文件在维护锁下重新执行，并会明确拒绝管道或进程替换输入。

### 固定正式版本

对供应链要求更高的环境，请使用 README 中的[固定版本验签流程](../README.md#更严格的固定版本验签安装)。它会依次检查：

1. 固定版本 Release 资产；
2. Cosign 二进制的固定 SHA-256；
3. 安装器的 GitHub Actions OIDC/Sigstore 身份；
4. 安装器 shell 语法；
5. 全部通过后才用 root 执行。

## 交互参数

安装器会询问：

- 分享链接中的节点名称；
- Hysteria 节点域名或公网 IP；
- Hysteria UDP 主端口；
- 面板 TCP 端口；
- 面板使用 HTTP 还是 HTTPS；
- HTTPS 面板的独立公网域名；
- 管理员账号和密码。

无人值守部署可使用以下环境变量：

| 变量 | 说明 |
|---|---|
| `NODE_NAME` | 分享 URI 中显示的节点名称 |
| `PUBLIC_HOST` | Hysteria 用户连接地址 |
| `HYSTERIA_PORT` | Hysteria UDP 主端口 |
| `PANEL_PORT` | 管理面板 TCP 端口 |
| `PANEL_SCHEME` | `https` 或明确接受风险后的 `http` |
| `PANEL_PUBLIC_HOST` | HTTPS 面板域名 |
| `EGRESS_POLICY` | `full` 或 `web` |
| `ADMIN_USER` | 初次安装的管理员账号 |
| `ADMIN_PASSWORD` | 初次安装的管理员密码，至少 8 个字符 |
| `RESET_ADMIN=1` | 升级时明确重置管理员 |

端口必须填写 `1`–`65535` 的十进制整数，不带前导零，例如使用 `443`，不要填写 `0443`。

不要把真实密码写进 shell 历史、Git、Issue 或 CI 日志。生产环境更适合在短时 root 会话中安全注入环境变量。

## 安装器会修改什么

安装器会部署：

- 面板程序、本机 Hysteria 和 TCP 兼容探测；
- 独立的面板 TLS 与 Hysteria TLS 身份；
- systemd 服务、恢复任务、定时备份和证书续期；
- 项目专用 sudoers 白名单；
- 至少 16 MiB UDP 缓冲，以及内核支持时的 `fq`/TCP BBR；
- UFW 或 firewalld 中由本项目拥有的端口规则。

安装器不会修改云安全组、托管 DNS 或客户端配置，也不会把面板 TLS 与 Hysteria 节点证书混用。

## 重复运行与升级

在已有受管安装上重复运行安装器会进入升级流程。升级会保留：

- 管理员和数据库；
- 用户 URI、认证身份、设备与流量限制；
- HMAC、统计密钥和节点来源 ID；
- Hysteria 证书、私钥和固定指纹；
- 当前端口、面板协议和出站策略；
- 数据节点 Ed25519 身份与 durable traffic spool。

覆盖程序前，安装器会暂停面板写入、结算流量、截断 SQLite WAL、创建带 SHA-256 清单的一致性备份，并持久化可跨重启恢复的事务标记。任何步骤失败都会尝试恢复完整旧状态，而不是留下半升级服务。

从 v0.39.43 起，升级会先停止新认证并尝试清退已有 QUIC 会话。若空闲连接没有响应踢出请求，安装器会临时隔离本机 Hysteria 对应的 UDP 入口，让连接按协议超时退出；统计进程保持运行，确认会话清空后才结算，不能把超时视为结算成功。此阶段客户端会短时断线，日志会显示常规清退、临时隔离与清理完成。

隔离只使用独立的临时 nftables 表，不改写现有 UFW/firewalld 规则。端口集合在内核中 120 秒自动到期，独立 systemd 定时任务在约 150 秒清理空表，正常或异常退出时会提前清理。即使升级进程被强杀，也不会无限期阻断入口。统计请求、隔离或清理失败会中止升级并沿用原有恢复流程；不要通过强停 Hysteria 绕过流量结算检查。

### 面板内在线更新

“检查更新”只查询固定 GitHub Release 来源。“立即更新”只能启动固定的 `hysteria2-panel-update.service`，浏览器不能指定版本、URL 或命令。

更新目标在排队时固定为一个 `vX.Y.Z` 正式版本。任务会验证安装器版本、Sigstore 身份、解释器头和 shell 语法；只有任务成功结束且新进程版本达到目标值，页面才会显示成功。

### 从旧 HTTPS 安装升级

历史版本可能复用了 Hysteria 节点证书作为面板证书。此类安装必须人工运行一次安装器，补充独立的 `PANEL_PUBLIC_HOST`。在线更新会拒绝缺少该字段的旧 HTTPS 配置，避免静默延续错误的证书边界。

## 安装后验收

至少完成以下检查：

1. `systemctl is-active hysteria2-panel hysteria2-panel-server` 均为 `active`；
2. 面板 `/healthz` 与 `/readyz` 返回 HTTP 200；
3. 面板端口和 Hysteria UDP 主端口正在监听；
4. 使用真实客户端和新建测试账号完成 Hysteria 握手；
5. 获准账号可使用 UDP `443`，未获准账号会被拒绝；
6. 流量会写入用户总量与对应机器统计；
7. 下载并验证一份完整备份。

TCP `19999`/`443` 只用于兼容连通性探测，不代表真实 UDP/QUIC 数据面可用。ICMP `ping` 也不属于 Hysteria 可用性验收。

## 常见停止原因

| 现象 | 先检查什么 |
|---|---|
| HTTPS 证书申请前停止 | 面板域名是否有公网 A/AAAA、是否指向本机、TCP `80` 是否可达 |
| 防火墙检查停止 | 是否同时启用了多个管理器，或存在安装器无法证明安全的自定义规则 |
| 在线更新被拒绝 | 当前是否为受管安装、是否配置独立面板域名、是否已有维护任务运行 |
| 升级后仍显示旧版本 | 查看更新服务状态和日志，不要重复点击或手工覆盖文件 |
| 数据节点对接失败 | 确认面板 HTTPS、来源 IP、短时命令有效期、系统依赖和云安全组；查看节点 onboarding 服务日志 |

继续排障时请看[运维手册](OPERATIONS.md)。

### 本人查询安装验收

安装器在健康检查后验证 `/api/v1/user/usage` 的无凭据响应：HTTPS 必须为 401 `INVALID_CREDENTIALS`，HTTP 必须为 403 `HTTPS_REQUIRED`。HTTPS 使用实际面板域名校验证书和主机名，通过本机地址连接，不关闭证书验证；失败进入既有事务恢复流程，不改变面板端口或代理配置。

六平台安装 E2E 会在临时 Docker/systemd 主机的新装结果上启用测试 CA 签发的 HTTPS，验证合成账号的零值、账本写入、重启、密码轮换及删除隔离。此项不代表公网 ACME 签发、真实节点转发或生产账号联调；新服务器仍需满足域名解析、端口可达、证书签发及支持的系统条件。

### 旧版备份恢复兼容性

v0.39.10 修复 v0.39.9 恢复旧备份时的收尾校验问题：备份副本先迁移到当前结构，再严格比较业务数据；本机新建来源沿用已恢复的创建时间，重试不受时间变化影响。六平台 E2E 包含旧格式备份经 systemd 完成恢复、服务重启和 HTTPS 本人查询验证。遇到未完成恢复事务时应保留数据库、原备份和事务标记，不能靠删除标记强行启动。


### 用户备份与新服务器验收

v0.39.11 的推荐顺序为部署新面板、恢复用户备份、再对接节点。恢复不复制旧机器或节点信息，保留目标机器预算。安装验证同时覆盖新用户备份和缺少旧表的 v0.39.7 备份，经真实 systemd 恢复后检查严格 HTTPS 本人查询和目标预算连续性。

“新服务器可部署”以 Ubuntu 24.04、Debian stable、Rocky 9 的 amd64/arm64 六平台安装验收为边界。域名解析、云安全组、ACME/GitHub 可达性及操作系统差异仍需安装器预检，不能承诺任意服务器零条件部署。


### HTTP 误访问与磁盘预检

默认入口为 `https://面板域名:19998/`。从 v0.39.44 起，误用 `http://面板域名:19998/` 的 GET/HEAD 导航会在同一端口返回 308，跳转到配置域名的 HTTPS 登录页；不保留原路径和查询参数，不处理明文登录、API 写入或 Cookie 会话。此功能不额外监听 80 端口，也不影响 Certbot 续期。API 客户端仍应直接使用 HTTPS。

安装器在依赖安装前（基础工具齐全时）及载荷下载前检查磁盘空间。同一文件系统的预算累加：暂存 192 MiB、安装载荷 192 MiB、依赖开销 /usr 和 /var 各 128 MiB、配置 16 MiB、状态 64 MiB，加已有安装的备份估算；每个涉及的分区额外保留 64 MiB。新装且全部位于同一分区时，最低预算约 784 MiB；升级还需备份空间。该预算是保守预检，不保证任意系统包升级或并发写盘均不会耗尽空间。

提示空间不足时，根据报错所列分区扩容或清理无关文件后重试；安装器不会自动删除恢复备份。`/tmp` 为内存盘时使用磁盘上的 `/var/tmp`，两处均为内存盘则停止。独立挂载的安装、配置、状态及备份目录分别检查。

# 备份与迁移

完整备份可以在新服务器恢复用户连接所需的身份，因此应把它当作高敏感凭据，而不是普通报表。

## 备份包含什么

格式 3 备份用户数据及面板本机节点的连接身份，让使用该节点的普通用户无需刷新订阅即可重新连接：

- 普通和专线用户名称、账号类型、认证与订阅身份、启用状态、开通和到期时间；
- 累计上传/下载流量、流量额度、设备数限制及账号权限；
- 已删除用户名的隔离记录，防止旧身份复用；
- 面板本机 Hysteria TLS 证书与私钥、原代理地址和 UDP 端口、端口跳跃开关。

不包含服务器管理记录、远端节点配置和证书、默认或独立节点列表、外部节点、管理员、会话、审计、历史明细和机器账本。在线设备数量不是设备数限制，不备份实时在线状态。

恢复替换目标用户，保留目标管理员、节点配置及机器账本；浏览器与移动端会话失效。用户累计用量作为未归属历史导入，避免恢复后重置已用额度。目标面板已有的外部 AnyTLS 节点保留，并随恢复的签名密钥重新加密；来源外部节点不会进入备份，新面板需重新配置。

## 格式和兼容

新备份固定包含：

```text
manifest.json
data/panel.db
secrets/hmac-key.hex
tls/server.crt
tls/server.key
```

`formatVersion` 为 3，不接受旧格式。更新面板后需要重新生成备份。
订阅的域名、协议、端口与路径必须保持不变；面板本机代理地址和 UDP 端口也必须保持一致，恢复预检会拒绝不一致的部署。
恢复会覆盖本机节点证书、私钥和相关身份参数，并恢复端口跳跃开关。原域名须指向新服务器，且原 UDP 入口及跳跃范围可达，普通用户缓存的本机节点配置才能继续使用；已有连接会中断后重连。远端服务器重新对接后仍需刷新订阅获取其新配置，专线证书不在此备份范围。

SQLite 在线快照、文件摘要、数据库完整性和身份校验仍执行。恢复前自动保存目标完整状态用于本机故障回滚；该回滚快照不是可下载的用户与本机连接身份备份。

## 下载与保管

在顶部打开“数据迁移”，选择下载用户备份。下载完成后：

1. 将文件保存到加密磁盘或离线介质；
2. 不要上传到公开网盘、Issue、聊天群或工单附件；
3. 至少保留一份与生产服务器分离的副本；
4. 定期在隔离环境验证备份可读，而不是等故障后第一次测试。

如果面板明确使用 HTTP，下载和上传过程没有传输层加密，只能在可信网络中操作。生产环境应优先使用 HTTPS。

## 迁移中央面板

1. 更新旧面板并下载格式 3 用户与本机身份备份。
2. 部署新面板，保留原订阅地址；按原代理地址、UDP 端口部署；节点证书由备份恢复。
3. 在对接服务器之前恢复用户备份。
4. 核对普通与专线用户数量、订阅身份、累计流量、流量额度和设备限制。
5. 重新对接服务器，将原订阅域名 DNS 切换到新面板。
6. 使用原订阅链接刷新，验收普通和专线连接、用量统计和设备限制。

已有对接节点的目标仍执行身份冲突检查，防止旧连接与恢复后的账号混用。恢复任务采用持久事务，失败回滚，重启后继续完成健康检查。不要手工替换数据库或删除恢复标记。

## 每日 WebDAV 异地备份

安装器会启用 `hysteria2-panel-offsite-backup.timer`。若要上传到 HTTPS WebDAV，请在服务器创建 root-only 配置：

```bash
install -o root -g root -m 0600 /dev/null /etc/hysteria2-panel/offsite-backup.json
editor /etc/hysteria2-panel/offsite-backup.json
systemctl start hysteria2-panel-offsite-backup.service
systemctl status hysteria2-panel-offsite-backup.service hysteria2-panel-offsite-backup.timer
```

配置格式：

```json
{
  "endpoint": "https://backup.example.com/hysteria2-panel/",
  "username": "专用备份账号",
  "password": "专用备份密码"
}
```

要求：

- `endpoint` 必须以 `/` 结尾；
- 目录支持中文和空格，也接受已做 URL 编码的路径；已有 `%xx` 转义会保留，不要重复编码；
- 只能使用 HTTPS；
- URL 不能包含账号、查询参数或片段；
- URL 不能包含换行等控制字符；指定端口时必须在 `1`–`65535` 范围内；
- 文件必须保持 `root:root 0600`；
- 应使用权限受限的专用 WebDAV 账号。

任务会以临时名称上传、验证远端尺寸和回读内容 SHA-256，再通过原子 MOVE 生效；正式对象再次回读校验成功后才记录成功。只删除超过 30 天且名称精确匹配本项目格式的远端备份。未配置目标时，任务只记录 `not_configured`，不会制造重复本地 ZIP 或误报成功。

每日任务调用与网页下载相同的归档生成器，因此 WebDAV 上传的是已经精简并完成最终自校验的归档，不会另行复制在线数据库或上传未验证的中间文件。

每日任务备份 SQLite 在生成时已经提交的数据，不会启动已停止的代理服务，也不会额外清零内核统计或处理面板的待入账日志。尚在内核或重试日志中的流量由面板正常采集后进入后续备份；实时在途流量不属于这份快照。网页手动下载继续使用面板自身的采集流程先结算再生成归档。

异地目标是服务器级秘密，不会进入可迁移 ZIP。迁移到新服务器后，需要重新创建这份配置。

## Hysteria 证书生命周期

节点证书指纹固定在已发放 URI 中。安装器升级会逐字节保留证书与私钥；格式 3 备份恢复会恢复来源面板的本机证书与私钥；项目只在 180/90/30 天时告警，不会自动续签或轮换节点证书。

人工更换节点证书会产生新指纹，旧 URI 必须更新并重新分发。操作前应先下载并离线验证用户备份，再安排维护窗口和客户端迁移计划。面板 Let’s Encrypt 证书与 Hysteria 节点证书是两套独立身份，不要混用。

## 开发验证合同

备份实现变更至少运行以下测试层级：

1. `tests/test_portable_backup_compaction.py`：表分类、10 万条以上运行时账本、体积、权限、失败清理、真实恢复和 WebDAV 精简归档；
2. `tests/test_backup_streaming.py`：SQLite/WAL 在线快照、流式大小上限、空间预检和证书有效期；
3. `BackupManagerTests`：旧格式 1、ZIP 结构、哈希、数据库损坏、证书/私钥不匹配、管理员保留和恢复回滚；
4. `tests/test_offsite_backup.py`：`O_NOFOLLOW`、同一文件描述符上传、临时远端对象、原子 MOVE 和保留策略；
5. 数据库、来源流量和节点控制测试，以及完整单元测试、安全静态检查和 `git diff --check`。

测试只使用临时数据库、测试证书和保留地址，不读取真实备份，也不得输出 HMAC、TLS 私钥、用户 token 种子或节点凭据。

异地上传先验证临时对象内容，MOVE 后再回读验证正式对象；内容验证失败不会记录成功或清理旧备份。节点人工用量调整的秒级批次边界见[完整教程](QUICKSTART.md#修改已用流量的时间边界)。

## 公网域名与服务器内部主机名

新部署、升级及恢复前，内部主机名必须与面板域名、普通节点域名分开，例如内部名称使用 `hy2-panel-internal`，公网仍使用原来的面板和节点域名。
部分系统会为本机主机名合成链路本地 IPv6 地址；节点的内网 ACL 会拒绝它，造成连接本机节点后面板、订阅和账号统计不可用，而专线访问正常。

安装器在停止服务和写入部署数据前检查；恢复上传/预检、实际应用及恢复健康验收也检查。发现冲突会明确拒绝，不修改订阅链接或放宽 ACL。备份下载仍可使用，方便先保存数据。

处理方式：由管理员执行 `hostnamectl set-hostname hy2-panel-internal`；如使用 cloud-init，在 `/etc/cloud/cloud.cfg.d/99-preserve-hostname.cfg` 设置 `preserve_hostname: true`，避免重启时还原旧主机名。清理 DNS 缓存后重试，并在重启后复核 `hostname`。若 `/etc/hosts` 手工将面板域名指向内网地址，也需修正该本机覆盖。

不要修改公网 DNS 名称、订阅 URL、端口、证书或用户密钥来绕过检查。用户备份不迁移操作系统主机名及 cloud-init 设置；新服务器需要独立检查。防护仅检查本机主机名冲突，不替代公网 DNS、代理链路和第三方客户端实际验收。

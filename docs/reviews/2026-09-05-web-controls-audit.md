## 确认并修复的问题

| 问题 | 复现与影响 | 修复与回归 |
|---|---|---|
| FULL 慢切换时，网页连接提前断开 | 普通 HTTP 请求总期限为 30 秒，出口切换允许等待 330 秒。操作较慢时，浏览器先收到连接关闭，后台仍可能切换成功，网页不能准确反馈结果。缩短期限的故障注入复现了 `RemoteDisconnected`，且后台状态已变为 FULL。 | 已认证、完成 CSRF 校验的出口操作复用既有维护请求期限。新增 HTTP 回归分别验证 full/web 跨过普通期限后仍返回 303；真实浏览器验证正常开关、取消、慢切换和后端失败提示。未放宽未认证请求期限。 |
| 恢复任务排队后仍可重复提交 | 第一遍显示“恢复任务已启动”，第二次点击又上传归档，后端拒绝后把成功提示覆盖成“已有恢复任务正在等待或执行”。后端没有重复执行恢复。 | 上传期间禁用按钮并阻止重复提交；成功后保持“恢复已启动”，失败后恢复重试能力。新增执行实际页面 JavaScript 的回归，覆盖无文件、取消、上传中重复提交、失败重试及排队后重复提交；浏览器使用真实 ZIP 下载和上传再次验证。 |

实现见 [FULL 请求处理](../../hysteria2_panel.py)、[恢复按钮](../../hy2panel/web_assets.py)。安装器已同步两个受影响源文件的 SHA-256。没有变更数据库结构、备份格式或节点协议，也没有新增生产依赖。

## FULL 的实际作用范围

FULL 控制面板所在服务器上的两个 Hysteria 配置，包括主 UDP 端口与 UDP 443。已对接的远程节点不会收到实时策略广播；新节点部署会采用当时的中央策略。这是当前功能边界，不应把网页开关理解为整个节点集群同步切换。

本轮生产只读检查确认：当前版本为 v0.39.5，FULL 实际状态与配置均为 `full`，两种出口切换单元的最近执行结果为成功。它们是 oneshot 单元，完成后显示 inactive 是正常状态。本轮没有在线上切换 FULL 或执行停止、重启、恢复、断连等操作。

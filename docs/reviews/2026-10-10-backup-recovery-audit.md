# 备份与恢复后续审查

日期：2026-10-10。延续[上一轮审查](2026-10-10-followup-audit.md)，跟查异地备份、恢复事务、节点身份切换及计量故障后的恢复路径。基线为 `70f572aa580451e18301bbc35b1d1ca1dad425ce`，工作分支为 `codex/project-audit-fixes`。本轮新增确认 1 项 P1、2 项 P2，均已修复；改动仍为本地候选，尚未发布。

## P1：异地备份的第二个计量器误删待入账日志

实际 `offsite-backup` CLI 在生成归档前调用 `sync_traffic`，另建一个 `UsageManager`。运行中的面板和 root 备份进程各持有内存批次，但共用 `pending-traffic.json`，并未建立两进程交接协议。

使用真实 SQLite 和持久化日志注入两次写入故障：面板持有未完成的 100 字节批次，备份进程补交该批次后又保存一笔 200 字节的新批次；面板重试旧批次时删除了新日志，最终数据库只有 100 字节，200 字节失去持久重试依据。经过实际 CLI 工厂的回归还使用 5 字节历史基线，修复前总量为 105，正确结果应为 305。

现移除异地任务的额外清零采集，复用原有归档生成器读取 SQLite 已提交快照。待入账日志和内核计数继续由面板采集进程处理。修复后 CLI 不读取或清零统计，不改写待入账日志，面板恢复后总量正确达到 305；已提交的 5 字节快照仍能通过归档自校验。相关取舍见 [ADR 024](../decisions/ADR-024-offsite-backup-accounting-isolation.md)。

每日备份可能不包含尚在内核或重试日志中的流量，这些记录提交后进入后续备份。网页手动下载仍在面板自身采集器内先结算再生成归档。

## P2：每日备份拉起管理员已停止的代理服务

安装器生成的异地备份单元把代理服务列在 `Requires` 中；启动定时任务时，该依赖会在检查 WebDAV 配置之前启动代理。此结论由实际单元内容和 [systemd 官方依赖语义](https://github.com/systemd/systemd/blob/main/man/systemd.unit.xml)确认，本轮没有将静态依赖检查描述为真实 Linux 运行证据。

现保留面板服务依赖及启动顺序，移除对代理入口的启动依赖。结合已提交快照方案，统计端点停止时也可生成备份。回归覆盖单元依赖、停止端点和实际 CLI 归档；[systemd 集成脚本](../../tests/systemd_integration.sh)新增从安装器抽取真实依赖、启动备份后检查代理仍为 inactive 的探针，本机完成脚本检查，真实 Linux 执行仍待验证。

## P2：合法的中文或空格 WebDAV 目录无法备份

配置加载允许 `https://backup.example.test/备份/` 和 `https://backup.example.test/backup files/`。请求只编码生成的文件名，直接拼接未编码的目录。因此 Python HTTP 客户端在发送前分别抛出 `UnicodeEncodeError` 和 `InvalidURL`，上传与失败后的临时对象清理都无法到达服务器。MOVE 的绝对目标地址和 GET 回读也使用同一路径。

修复在配置入口集中规范化地址，上传、尺寸查询、回读、MOVE、目录查询和删除共用同一结果：

- 中文和空格目录转为 UTF-8 URL 编码，已有转义保持原样，尤其不把 `%2F` 变成路径分隔符；
- 国际化主机名转换为 IDNA，保留 IPv6 方括号与非默认端口；
- 在生成归档前拒绝控制字符、非法端口及无法编码的字符串，避免解析器静默移除换行后访问另一个路径。

配置字段、凭据处理、TLS 证书校验和备份命名规则保持兼容。安装器内的异地备份模块 SHA-256 已同步。

## WebDAV 路径复现与回归

[新增回归](../../tests/test_webdav_paths.py)首先加载本轮修改前的模块，重现请求序列化失败；然后针对修复版本运行。真实回环 TLS 服务只在测试环境中被加入信任，主机名校验保持开启。

三个完整流程分别使用中文目录、空格目录和含已有 `%2F`／`%25`／`%20` 的混合目录，核对以下顺序和服务端最终内容：

`PUT → HEAD → GET → MOVE → HEAD → GET → PROPFIND → DELETE`

临时对象与正式对象均回读并校验 SHA-256，MOVE 目标目录保持一致，过期备份在正式对象验证成功后删除。另两项测试覆盖 IDNA／IPv6 目标 URL 生成，以及七类无效配置。原有同长度损坏、上传中修改、MOVE 失败和旧备份保护回归继续通过。

[备份隔离回归](../../tests/test_offsite_isolation.py)另有 4 项，覆盖实际 CLI 调用、真实 SQLite 归档、待入账日志失败后恢复和安装器依赖。修复前这 4 项均失败，修复后全部通过。

## 其他路径复核

- 恢复前继续校验已对接节点的 HMAC、证书和同名账号身份，冲突在替换在线数据前拒绝。
- 恢复保留目标机器、节点与预算，替换用户资料后清理会话和在线快照，并排队清退旧连接。
- 恢复持久标记、磁盘状态核验、分阶段继续和回滚路径维持既有约束；没有为本轮地址修复改写恢复事务。
- 节点协议请求重新读取注册状态，并按目标地址管理传输上下文；未将文档明确保留的重绑定账本判为新缺陷。
- 异地任务由 systemd 的 30 分钟上限约束；网络读取仍保持已有响应大小、超时和内容校验限制。

这些复核中暂未新增确认其他缺陷，不代表所有生产组合都已验收。

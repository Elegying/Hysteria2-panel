# 2026-09-05 部署与持久化可靠性审查

审查基线：`ccf2d3ca3ebcff2a854207f95db806b4c85c7993`（源码版本 `0.39.4`），修复记录在 `Unreleased`。本次使用本地源码、隔离测试数据和临时运行时，未连接生产服务器、未发布版本。原有 `docs/README.md` 和 `docs/FUNCTION_ACCEPTANCE_BASELINE.md` 工作区改动未修改。

本轮确认并修复七类可复现问题，另同步了过时操作文档和 CI 检查范围。项目已有签名分发、受限命令、升级/恢复事务、流量重放和备份校验等重要保护；主要维护风险是安装器和中央入口规模较大，以及部分系统行为仍必须依靠 Linux 集成环境验证。

## 已修复的问题

| 编号 | 优先级 | 原行为与影响 | 修复与回归证据 |
|---|---|---|---|
| F01 | P1 | 节点最多保留 256 条已完成命令，但状态文件只允许读取 4 KiB。使用正常时间戳连续完成第 55 条命令时，文件达到 4,152 字节，后续状态读取报错；控制循环、流量结算和新连接状态会受影响，重启也不能修复文件。 | [ProtocolState](../../node_agent.py) 的有界读取合同扩大至 32 KiB，保留原有 256 条去重历史和 `0600` 权限。回归连续写入 260 条命令，重启后检查淘汰边界、序列、流量 ACK 和停用状态，并保留超限拒绝测试。 |
| F02 | P2 | 节点对接绕过系统依赖补装。缺少 Python/OpenSSL 时立即失败；缺少 `cmp`、`ss`、`nft` 等后续工具时，可能注册成功后才卡在后台收尾。BBR 为可加载模块时还需要 `modprobe`。 | [安装器](../../install.sh) 复用现有 `apt`/`dnf`/`yum` 安装与有限重试逻辑，在对接、收尾、重绑定和激活路径统一按需检查依赖，补齐 `kmod`。隔离 shell 回归覆盖六种依赖缺失、已满足时不重复安装、软件源失败时停止后续操作。 |
| F03 | P2 | Python 选择仅检查版本，带有解释器但缺少 SQLite 等标准库的系统会被当作可运行，直到后续启动才失败。 | [select_python](../../install.sh) 同时导入 SQLite/SSL 并检查 scrypt。回归让 SQLite 导入实际抛出异常，旧检查错误放行，修复后拒绝该解释器并进入依赖补装路径。 |
| F04 | P2 | 端口接受任意长度数字，再交给 Bash 算术处理；`080`、`0443`、`0100000` 和溢出长整数可绕过原范围检查，字符串比较也不能可靠识别等价端口。 | 五个端口入口统一只接受不带前导零的 1–5 位十进制整数，再检查上限 65535；在防火墙和服务配置前拒绝。回归覆盖正常边界、零、超上限、八进制形式与整数溢出。 |
| F05 | P2 | WebDAV 将响应头转成普通字典后，只读取 `Content-Length`；服务器使用小写或大写字段名时，正常备份也会被报成尺寸不可用。 | [HttpsWebDavClient](../../offsite_backup.py) 按不区分大小写的字段名取值。回归覆盖标准、小写和全大写三种形式。 |
| F06 | P2 | 临时对象在校验远端尺寸前就被 MOVE 成正式备份名；上传被截断时会留下看起来正式的损坏对象。 | [WebDavBackupStore](../../offsite_backup.py) 在 MOVE 前先检查临时对象尺寸，失败清理临时对象、不执行历史保留清理；移动后的最终尺寸复核继续保留。回归模拟服务端截断上传，确认不发布正式对象、不枚举或删除旧备份。 |
| F07 | P2 | Android 管理端刷新登录时捕获所有异常并删除刷新令牌，短暂超时、503 或代理异常页面都会导致永久退出登录。 | [AppController](../../mobile/lib/core/app_controller.dart) 只在明确收到 401 时清除凭据；其余错误保持会话并允许页面重试，修复共享刷新 Future 的异常传播。使用现有 Dio 注入合成响应和安全存储 mock，覆盖三类启动故障后的恢复、明确过期清理、并发刷新失败后的再次成功。 |

这些边界有明确外部依据：Bash 将前导零常量解释为八进制，见 [GNU Bash 算术规则](https://www.gnu.org/software/bash/manual/html_node/Shell-Arithmetic.html)；HTTP 字段名不区分大小写，见 [RFC 9110 §5.1](https://www.rfc-editor.org/rfc/rfc9110.html#name-field-names)。精简解释器与完整标准库也确实分包，见 Debian 的 [python3-minimal](https://packages.debian.org/trixie/python3-minimal) 和 [标准库包](https://packages.debian.org/trixie/libpython3.13-stdlib)。

## 发布前仍需完成

1. 在候选提交上通过现有 Ubuntu、Debian、Rocky amd64/arm64 六平台矩阵，以及真实 UFW/firewalld 和 systemd 门禁。
2. 使用干净 Linux 数据节点验证依赖自动补装、一次性对接、双 UDP 客户端握手、断网重放、重启恢复与一键断连。检查旧节点超过 55 条命令的状态文件可被新 Agent 恢复读取。
3. 在真实 HTTPS WebDAV 上验证上传、尺寸校验、MOVE、权限和下载恢复；保留至少一份已验证的离线备份。
4. Android 真机验证断网启动、恢复网络、令牌过期、退出登录和系统安全存储，发布时继续使用原有签名与 ABI 门禁。

本次没有为拆分大文件重写关键事务。后续结构改进应围绕可独立测试的数据库、安装预检和恢复边界逐步开展，并保持用户身份、协议、签名分发和回滚语义兼容。

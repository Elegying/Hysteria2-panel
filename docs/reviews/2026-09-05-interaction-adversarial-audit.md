# 交互与异常路径再审查

本轮针对前两轮审查的覆盖缺口展开，基于 v0.39.5 工作区继续修复。新增确认 5 类问题；加上[上一轮 FULL 与恢复按钮](2026-09-05-web-controls-audit.md)的 2 类问题，该轮结束时本地分支包含 7 类修复。后续发现、验证和当前累计结果见[并发与生命周期续审](2026-09-05-concurrency-lifecycle-audit.md)。这些本地修复不能视为线上已经修复。

## 前两轮为什么会遗漏

原 CI 的浏览器任务调用 `.github/scripts/browser_smoke.py`，把已认证 HTML 保存成本地文件后截图，主要证明页面可以渲染。后端测试覆盖了大量权限、持久化、协议和故障边界，但没有把按钮点击、等待、关闭、刷新和最终反馈串成完整浏览器验证。此前对测试数量的汇总没有充分突出这个缺口。

因此，“全部现有测试通过”只能证明现有测试覆盖的场景通过，不能证明全部用户操作及其组合均已验证。不能要求用户代替审查者指出每个按钮；此次把临时实点检查转为仓库内持续门禁。

## 新增确认与修复

| 编号 | 真实问题和复现 | 修复与验证 |
|---|---|---|
| I01 | 更新正在排队时刷新页面，状态仍显示排队，按钮却恢复“立即更新”，并丢失轮询。更新状态请求一直挂起时，原有总等待期限无法生效；失效会话会被误报为面板重启；原来的“检查状态”仍会提交更新。 | 活跃更新在刷新后自动继续跟踪，即使进程已丢失此前的版本查询缓存也能恢复。单次状态请求有 8 秒期限，401 返回登录；超时表明结果未知，失败/超时后的按钮只刷新页面，避免重复发起更新。真实浏览器和实际页面 JavaScript 回归覆盖刷新、失败、无响应、失效会话和只读重试。 |
| I02 | 生成对接代码时关闭弹窗，迟到响应仍重新填入代码；再次打开会看到上一轮残留。 | 绑定弹窗请求代次，关闭后使旧响应失效。真实浏览器延迟响应、关闭并重开弹窗，验证代码和结果区保持清空。 |
| I03 | 移动 API 使用 `bool()` / `int()` 强制转换输入。`"allowUdp443":"false"` 实际创建了允许 UDP 443 的用户；小数和布尔版本号也可能被当成整数接受。 | 在共享移动 API 边界要求真正的 JSON 布尔值与整数。创建、编辑、用户操作和删除复用校验；HTTP 回归覆盖字符串、布尔值、小数及无穷值，并确认无效请求不改动用户。正常 Android 请求使用的类型保持兼容。 |
| I04 | Android 编辑用户对空白或非数字输入直接 `int.parse`，产生未处理的 `FormatException`；新增用户对无效输入直接返回，没有提示。 | 新增与编辑共用额度校验，显示明确的字段和接口错误。组件测试实际输入空白、字母、越界值、小数和合法值并点击提交，检查无效输入没有发送请求；覆盖 390×844 视口与 300 像素键盘占位。 |
| I05 | 服务启停或状态查询出现 `TimeoutExpired` / `OSError` 时，异常未转换为网页处理器可处理的错误，可能直接关闭连接。 | 在共享服务控制器统一转换错误，网页明确显示“操作结果未能确认”，要求刷新状态。回归覆盖动作失败、后续状态查询失败和实际 HTTP 错误页面。超时不被当成服务已经停止或已经重启的证明。 |

修改沿用既有表单、控制器和维护请求机制，没有新增生产依赖、数据库格式、任意远程命令或节点协议。

## 持续门禁的改动

- 新增 [真实浏览器检查](../../tests/browser_controls.py)，使用回环 HTTP 面板、临时数据库、合成用户/节点和隔离系统控制器。覆盖登录、FULL、用户管理、复制/二维码下载、筛选/排序、预算、对接、更新、重启、备份恢复和退出，共 29 组交互。
- 原有桌面/手机截图检查保留；[CI](../../.github/workflows/ci.yml) 增加实点检查与实际 JavaScript 异常回归，检查 Node.js 存在，避免 JavaScript 测试因缺运行时被跳过。
- 浏览器测试传输依赖固定为 `websockets==17.1`，已验证从包源下载成功；仅浏览器测试任务安装，生产安装器不依赖它。
- Android 表单回归加入已有 Flutter 测试门禁，不新增测试框架。

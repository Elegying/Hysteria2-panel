## P1：节点旧允许决策绕过当前凭据和安全状态

中央协议服务通过签名、来源和 nonce 验证后调用 `authorize_distributed_node`。原实现找到同一 `(nodeId, requestId)` 的未过期允许决策时，只检查是否仍有安全清退命令，然后提前返回；当前凭据、入口权限、额度、设备数和全局快照检查都位于该分支之后。

使用真实 SQLite 和中央协议服务复现：先获得允许决策，再改密并排队清退。清退未 ACK 时旧请求被拒绝；模拟清退窗口结束并完成 ACK 后，用新 nonce 重试相同请求编号，旧 token 又得到允许。节点端最初决策有效期为 43 秒，因此清退完成不等于这个旧允许结果已经过期。

同一根因还确认了以下行为：

- 关闭 UDP `443` 权限后，旧允许决策仍放行；主入口的允许决策还可被同一请求编号用于未授权的 UDP `443` 入口。
- 请求携带无效凭据或另一个账号的有效凭据时，仍返回原账号的允许结果。
- 用户禁用、流量耗尽或设备限制调低后，缓存仍返回允许。
- 在快照剩余 1 秒有效期时取得决策，2 秒后重试，已经过期的快照被绕过，导致短决策缓存延长了实际状态可信窗口。
- 自动初始化授权重新签发并撤销旧授权后，旧自动验收凭据仍可复用先前允许决策。

这些请求仍需来自已注册节点并通过原有协议验证；本轮没有证明普通外部客户端可以伪造节点签名。节点回归使用测试签名校验器，确认的是通过协议验证后的准入逻辑。

修复把旧决策返回放到当前身份、权限、状态和容量检查之后，复用原有事务路径。当前凭据必须仍有效且属于原决策账号；初始化授权必须仍有效。已经允许的同账号重试承认原有一个设备预留，不重复占位；决策编号与到期时间保持不变，也不提前释放可能仍被在途连接使用的原预留。原拒绝结果不会因权限后来放宽而转为允许。

## P2：本机 UDP 443 权限撤销与认证等待之间存在竞态

`handle_auth_payload` 首先检查 token 与 UDP `443` 权限，随后 `UsageManager.authorize` 可能等待采集器、统计响应或数据库。最终预留设备名额的事务会重新检查启用、清退、流量与设备数，但原来没有重新检查入口权限。

[本机回归](../../tests/test_local_auth_boundary.py)运行真实回环认证 HTTP 服务和管理 HTTP 服务，在认证已经通过首次权限查询后暂停执行，通过实际网页表单或移动 API 关闭权限，再继续认证。以下四种组合修复前都返回 `{"ok": true}`：

| 管理入口 | 认证暂停位置 |
| --- | --- |
| 网页 | 等待统计采样 |
| 移动 API | 等待统计采样 |
| 网页 | 命中统计缓存后、最终准入事务前 |
| 移动 API | 命中统计缓存后、最终准入事务前 |

修复沿现有方法传递入口要求，在最终设备名额预留事务内再次检查。修复后四种组合均拒绝，并确认未增加本机租约；主端口继续可用，重新开放 UDP `443` 后原凭据能够正常认证。

## 继续复核

- 正常节点重试维持原决策编号、到期时间和单个容量预留，达到设备上限时不因重试被当作第二个连接请求。
- 当前设备占用高于调低后的上限时拒绝旧请求；缓存不会形成绕过新额度的例外。
- 本机和节点继续共用全局设备限制；暂停、停止中的节点仍按原有新鲜度和容量规则处理。
- 原有改密清退门禁在命令待确认期间保持拒绝；本轮补齐了命令已确认之后的旧凭据重试检查。
- 自查询流量继续独立于代理准入，不调用准入方法，不因本次修复给只读查询新增设备预留。
- 维护与手动流量调整的锁范围经过调用链复核，本轮没有确认可归因于该处的账本异常，也没有据此修改计量时序；该静态复核不等同于真实 Linux 并发维护验收。

# v0.39.27 发布前审查修复

本次针对 v0.39.26 审查确认的六项问题，修复用户删除、在线状态容量、旧额度清退命令、App 用户操作与发布文档。

| 问题 | 修复后的行为 | 回归入口 |
| --- | --- | --- |
| 删除账号的残留在线会话使其他节点的新认证失败 | 只过滤登记在退役记录中的身份，接受其余完整在线状态；真正未知身份继续拒绝 | `tests/test_release_readiness.py` |
| 单节点 1001 个在线账号导致整个控制周期被拒 | 完整在线映射按 UTF-8 字节限制为 480 KiB；流量合并超限时先确认流量，再独立发送完整快照 | `tests/test_release_readiness.py` |
| 月清零后仍领取旧额度踢人命令 | 额度命令保存用户 generation，领取时复核代际与当前用量；同批只移除已恢复资格的成员 | `tests/test_release_readiness.py` |
| App 用户请求等待期间可重复提交 | 同一用户从确认框到请求结束互斥，失败/取消后恢复操作 | `mobile/test/user_details_state_test.dart` |
| App 打开的用户详情保留旧状态 | 按 ID 使用最新列表数据，提交当前 generation；后台删除显示关闭入口，刷新保留未保存输入 | `mobile/test/user_details_state_test.dart` |
| 安装版本示例和节点删除文档漂移 | README 文案、可执行变量与当前正式版本一致；API 明确管理员可单方面删除在线、离线及断连中节点 | `tests/test_supply_chain.py` |

额度命令的新增元数据只存于中央数据库，线上仍发送兼容既有 Agent 的 `KICK_USERS`，没有扩大节点执行权限。禁用、改密、删除和恢复操作的安全清退不使用额度条件，不会被月清零取消。新增列可从既有数据库迁移，原先缺少原因的历史命令保留原语义，不推测取消；部署前检查待处理命令。

完整在线状态不截断账号，也不采用无限载荷。独立与合并请求的 HTTP 上限均为 512 KiB，预留签名/元数据空间。超过完整快照能力时保留明确失败及新认证关闭，已采集流量保持持久化和幂等重试。

Android 版本为 0.4.4（构建 26），保留既有玻璃组件、主题和背景；复用节点详情的刷新模式，没有新增动画或渲染依赖。

新回归覆盖退役身份与未知身份混合、其他节点认证、1001 个最长多字节用户名、合并请求超限后的完整快照、额度恢复与安全命令并存、重启后的条件保留、新周期再次超额、App 五类变更动作的重复点击、详情刷新/删除及未保存表单。

正式交付仍以候选提交的 Python、Flutter、浏览器、静态检查、精确标签六平台安装矩阵、签名资产和部署后验收为准。早期版本的绿色记录不能替代本次检查。

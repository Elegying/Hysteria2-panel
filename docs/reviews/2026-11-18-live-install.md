# 一键部署与节点对接实机验收

环境：两台空白 Ubuntu 26.04.1 amd64 云服务器，内存分别约 453 MiB / 956 MiB，根分区约 3.8 GiB。面板使用独立域名 HTTPS 19999，本机节点 UDP 443，远端节点内部主入口 19999、订阅入口 443；共享节点域名有两条灰云 A 记录。测试使用独立临时用户，凭据和完整连接信息不进入公开仓库。

## 已验证的正式版流程

以 v0.39.58 的公开短命令开始，不替换服务程序或绕过签名：

- bootstrap 校验 Cosign 固定哈希和安装器精确标签签名。
- 面板从空白服务器安装，依赖、Let’s Encrypt 证书、健康检查、流量计量、备份/续期 timer 完成，命令退出 0。
- 使用移动 Bearer API 开启 UDP 2000–50000 跳跃，转发到本机 443。
- 从面板生成一次性对接命令，在第二台空白服务器执行；身份注册、签名心跳、数据面部署、出网证明和中央确认完成，命令退出 0。
- 双向使用真实用户订阅，分别连接对端 443、2000、23456、50000；每次经 Hysteria2 完成 HTTPS 请求并验证出口 IP 等于目标节点 IP。
- 错误凭据被拒绝；同一个订阅身份保持不变，真实流量累计增加。
- 资源监控、近期/今日网卡历史和设置 API 正常；节点在线，数据面状态已准入，内核 fq/BBR 与 16 MiB UDP 缓冲生效。

以上是两个云服务器之间的真实数据面测试，不把 TCP 探针或进程存活当作代理出网证明。

## 发现与修复

1. **前置验签仍占内存盘**：bootstrap 原先用默认 `/tmp` 暂存约 135 MiB Cosign。面板安装器本体虽已避开 tmpfs，前置阶段仍可能给小内存服务器带来压力。新版先检查暂存文件系统，必要时改用真实的 `/var/tmp`；两处均为内存盘或备用目录为符号链接时停止。节点对接、重绑定、维护和激活同样使用受检暂存目录。
2. **自动跳跃验收覆盖旧范围**：自动 canary 原先从 20000 开始抽测，遗漏现行 2000 下界。新版覆盖 2000、2001–49999 随机端口和 50000，TCP 探针独立检查既有 20000–50000 范围，避免把 UDP 低端口误判为 TCP 故障。只影响验收覆盖，不更改客户订阅或 NAT 配置。
3. **无人值守文档遗漏订阅名称**：补充 `SUBSCRIPTION_NAME`，与现有实际参数保持一致。

4. **签名服务短时 DNS 超时**：重复执行正式安装时，Sigstore 信任根域名解析超时，安装器在服务修改前停止。新版最多重试三次签名验证；仍失败则安全退出，不跳过签名或改用未验证载荷。

增加回归覆盖普通磁盘、tmpfs/ramfs、双内存盘、符号链接备用目录、所有节点暂存路径以及跳跃边界。发布继续要求 PR/main/tag CI、六平台安装矩阵和正式签名门禁。

## 容量与验收边界

该类小磁盘镜像可能带有数百 MiB 的 APT 包缓存。升级还需要保存恢复备份，应先检查可用空间；可通过 `apt-get clean` 清理可重新下载的包文件，不能为绕过磁盘预检删除用户数据或恢复备份。安装器继续保留空间不足时安全停止的行为。

异地备份 timer 安装成功不等于已配置异地存储目标。本次未提供 WebDAV 目标，因此只验证未配置状态与本地备份能力。Android 界面改版不属于本轮部署修复范围。

# Hysteria2-panel 全项目审查

审查日期为 2026 年 10 月 10 日。范围包括后端与数据库、分布式节点、流量与配额、Web 与 Android、身份与权限、备份恢复、安装升级、发布流程和验收文档。

本轮确认 **1 项 P1、2 项 P2**：远端多连接清退不完整、超大流量响应在清零后丢失、App 删除登录记忆或退出时不能可靠撤销服务端会话。既有测试整体通过，但没有覆盖这三个组合条件。优先处理清退与计量路径，再完善会话撤销。

审查基线为提交 `70f572aa580451e18301bbc35b1d1ca1dad425ce`，面板与节点版本 `0.39.38`，Android `0.4.11+34`。工作区开始时干净；本轮只新增审查文档，未修改业务实现、提交代码或操作生产服务。所有新增复现使用临时 SQLite、合成账号和回环 HTTP。

## 已确认缺陷

### P1 远端踢人命令完成后仍有同账号连接存活

**位置：**[node_agent.py](../../node_agent.py) 第 2702–2704、3303–3308 行；[hysteria2_panel.py](../../hysteria2_panel.py) 第 5795–5815 行。

节点代理执行 `KICK_USERS` 时只调用一次 `/kick`，随后把命令记为完成并确认给中央面板。项目固定安装的 Hysteria `2.12.1` 将踢人请求保存为一个按账号索引的标记；首条连接的下一次流量事件消费并删除这个标记，其余连接继续被允许。上游随后关闭的是触发事件的连接。[固定版本上游实现](https://github.com/apernet/hysteria/blob/14e9fff1d972ab0187ac7fcf75b9514dc8664065/extras/trafficlogger/http.go#L52-L70)、[连接关闭位置](https://github.com/apernet/hysteria/blob/14e9fff1d972ab0187ac7fcf75b9514dc8664065/core/server/server.go#L339-L342)。

配额入账仅在用量第一次跨过上限时排入清退命令。多条连接中只有一条被清退后，剩余连接继续上传流量不会再次触发这一条件；远端没有对应的持续清退检查。因此，拒绝后续新认证不能终止所有已建立连接，超额账号仍可能继续传输。禁用、删除和改密也复用这一远端命令路径，应一并纳入修复验收。

复现分为两层：直接执行固定版本上游的真实 `trafficlogger` 测试，证实一次 `/kick` 后三次流量事件返回 `[false, true, true]`；再通过本项目真实数据库与命令执行函数，接入同样语义的统计接口替身，复现以下结果。

| 复现指标 | 结果 |
| --- | --- |
| 已建立连接数 | 3 |
| 账号配额 | 100 字节 |
| 首次入账 | 110 字节，产生 1 条清退命令 |
| 执行后剩余连接 | 2 |
| 后续 5 批流量入账后 | 用量 610 字节，待执行清退命令 0 条 |
| `/kick` 调用次数 | 1 |

这证实了上游语义与项目命令生命周期之间的缺口；没有把该复现当作真实手机、真实 QUIC 链路的端到端测试。

**修复方向：**把清退完成条件与目标连接的实际退出关联，保留可重试状态并定期核对。额度清退继续遵守账号代际和恢复额度后的取消规则；安全清退应明确目标旧会话，避免迟到命令误踢新授权连接。现有 `quiesce_traffic` 已处理“单次踢人只消费一条连接”的语义，可复用其中的观察与重试思想，不能直接把全节点排空用于单账号操作。

**回归要求：**同账号至少三条连接、空闲连接迟到产生流量、跨配额后的持续传输、节点重启与 ACK 丢失、月清零和改密后的代际切换。

### P2 节点流量响应超过读取上限时会永久少记流量

**位置：**[node_agent.py](../../node_agent.py) 第 76、2454–2463、2484–2487、3084–3098 行。

节点代理读取 `/traffic?clear=1` 时最多接收 `512 KiB + 1`，超过 512 KiB 就拒绝响应。固定版本上游在写出响应前已清空统计表。代理因此既拿不到完整结果，也没有可持久化的原始批次；再次采集只能得到清零后的数据。[上游清零时序](https://github.com/apernet/hysteria/blob/14e9fff1d972ab0187ac7fcf75b9514dc8664065/extras/trafficlogger/http.go#L130-L149)。

使用 2,550 个合法用户名复现，每个名称为 60 个汉字和 4 位数字，共 64 字符；各账号上传 100 字节、下载 200 字节。此输入仍符合当前完整在线快照的容量验证，不能归因于账号数量已经超出该能力。

| 复现指标 | 结果 |
| --- | --- |
| 完整在线映射大小 | 481,951 字节 |
| 当前在线映射上限 | 491,520 字节，`_online_mapping` 验证通过 |
| 流量 JSON 大小 | 527,851 字节 |
| 节点流量读取上限 | 524,288 字节 |
| 采集结果 | `ProtocolError: local traffic stats response is invalid` |
| 持久化流量批次 | 0 |
| 下一次采集 | `{}` |
| 此批丢失计量 | 765,000 字节 |

项目侧复现使用真实 `LocalStatsClient`、`NodeControlCycle`、`DurableTrafficSpool` 与回环 HTTP；上游测试另外验证了真实处理器的响应大小及清零顺序。账号名称和计数越大，达到字节上限所需的账号数量也会变化。此问题影响账本、配额和预算准确性。

**修复方向：**统一支持容量与破坏性读取边界，保证完整采样可持久化后才丢弃上游可恢复状态。评估有界流式落盘、可确认的批次协议或非破坏性差分采集；不能仅靠放大一个常量或吞掉异常来宣称无损。保留资源上限，并明确统计清零与进程崩溃之间的保证。

**回归要求：**响应在阈值前后、多字节用户名、大计数、双入口一侧失败、部分响应、落盘失败和重启；核对总账既不漏记也不重复记账。

### P2 App 删除登录记忆或退出后刷新凭证可能仍然有效

**位置：**[mobile/lib/core/app_controller.dart](../../mobile/lib/core/app_controller.dart) 第 71–88、575–583、638–649 行；[hysteria2_panel.py](../../hysteria2_panel.py) 第 7804–7808 行。

App 只持久化刷新凭证，重启时将访问凭证恢复为空，只刷新当前面板。删除另一个面板的登录记忆时，本地先清除会话，随后撤销函数因访问凭证为空而完全不发送请求。即使访问凭证存在，只要已经过期，服务端也会在进入退出逻辑前返回 401；App 丢弃失败结果，仍完成本地清除。

两种触发均已复现：

1. Flutter 控制器登录两个合成面板后重新初始化，删除未激活面板。本地登录信息已删除，刷新凭证原先存在，但退出 HTTP 请求数为 **0**。
2. 对真实回环面板 HTTP 接口，使用过期访问凭证退出返回 **401**；继续使用同一会话的刷新凭证返回 **200**，新访问凭证读取会话也返回 **200**。

这不是未登录用户可以直接登录的绕过；影响是本地退出与服务端会话撤销不一致。若旧刷新凭证已有副本，它不会因这次操作失效，会话默认刷新有效期为 30 天。

**修复方向：**为退出提供可凭刷新凭证安全识别并撤销对应会话的幂等能力，处理并发刷新；客户端明确区分本地清除与已确认的服务端撤销。网络不可用时允许本地退出，但应设计有界、可恢复的撤销流程，避免在没有发送请求的情况下丢掉唯一可撤销凭据。

**回归要求：**重启后的非当前面板、访问凭证过期、刷新与删除并发、网络中断、安全存储失败，并核对旧刷新凭证最终无法换取新会话。

## 处理顺序

1. 为远端多连接清退建立失败回归，修正完成条件和重试状态，保护配额恢复与安全操作语义。
2. 修复破坏性流量采集的容量边界，加入上限前后和重启后的账本守恒验证。
3. 完成 App 与服务端的会话撤销闭环，验证旧刷新凭证失效。
4. 更新当前功能验收基线，将这三个组合条件纳入持续回归。
5. 在上述行为受测试保护后，逐步抽取统计协议、清退和会话模块，降低大型入口的修改范围。

本轮没有直接修复这些问题。后续修复完成时，需重新运行相应回归与完整门禁，并单独安排真实节点和 Android 设备验收。

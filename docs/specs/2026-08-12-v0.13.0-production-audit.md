# v0.13.0 生产审查与节点身份连续性规格

## 背景

当前项目已经承载已发放的 Hysteria 2 节点。升级、重装和跨服务器恢复必须把“旧链接继续可用”作为最高优先级，不能以重新分享节点作为恢复手段。

## 不变量

- 不改变已发放 URI 的域名、UDP 端口、认证 token、证书或 `pinSHA256`。
- 不把 Hysteria QUIC 拥塞控制从官方 `BBR standard` 改成 Brutal 或 aggressive。
- 默认设备限制仍为 3，默认总流量仍为 250 GiB。
- 认证与统计接口继续只监听回环地址；默认 `web` 出站策略继续拒绝私网与非网页端口。
- 继续保持无第三方 Python 运行时依赖和单文件部署结构。

## 本轮目标

### 1. 节点身份与恢复

- 对备份中的 SQLite、HMAC、TLS 证书/私钥、域名和 UDP 端口执行恢复前校验。
- 写入完成后再次从磁盘验证数据库、HMAC、证书/私钥、证书指纹和环境文件；任何不一致必须自动回滚到恢复前快照。
- 增加多用户连续性回归：可恢复用户的 URI 必须逐字节一致，旧 token 必须继续认证，旧版不可逆 token 也必须继续认证。

### 2. 程序保活

- 面板 HTTP、内部认证或流量采集任一工作线程意外退出时，主进程必须以失败状态退出，让 systemd 的 `Restart=on-failure` 接管恢复。
- 正常停止仍由 systemd 控制，不新增循环重启或外部守护脚本。

### 3. 面板性能与界面

- 对支持 `gzip` 的浏览器压缩 HTML 响应；356 用户页面的传输体积应显著下降，敏感页面仍保持 `no-store`。
- 用户搜索按动画帧合并连续输入，避免每个键盘事件重复遍历全部用户行。
- 桌面端用户表头保持可见，统一数字排版、悬停和焦点反馈；移动端继续一行一个用户且不横向滚动。
- 尊重 `prefers-reduced-motion`，不引入前端框架或外部资源。

### 4. 部署与维护

- 继续固定并校验 Hysteria 与面板源码的 SHA-256。
- 核对 Debian/Ubuntu、RHEL/Rocky/Alma/CentOS Stream/Fedora、amd64/arm64、systemd 和 Python 3.8+ 合同。
- 更新版本、变更日志、README、API/ADR、实施计划和运维恢复清单，清除过期任务状态。

## 验收门

- 新增测试先失败，再完成最小实现。
- 全部 Python 测试、`py_compile`、`bash -n`、ShellCheck、Ruff、Bandit 通过。
- 356 用户响应进行压缩前后体积与耗时对比。
- 在真实浏览器检查桌面、375 px 手机宽度、登录、搜索、弹窗、复制与用户操作布局。
- 最后进行代码、安全、部署、运行、恢复和对抗性复审；未验证项必须明确列为残余风险。

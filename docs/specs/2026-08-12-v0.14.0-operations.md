# v0.14.0 可观测更新与运维控制规格

## 不变量

- 不改变已发放 URI 的域名、UDP 端口、认证 token、HMAC、TLS 证书或 `pinSHA256`。
- 编辑用户限额只修改 `device_limit` 和 `traffic_limit_bytes`，不得生成新 token。
- 继续保持无第三方 Python 运行时依赖、固定来源更新和 systemd 托管。
- 不宣称能够从标准 Hysteria 2 协议获得硬件设备指纹。

## 在线更新

- 点击更新后必须立即显示已排队，并轮询认证后的状态接口。
- 状态至少包含：空闲、排队、运行、成功、失败；不得把成功启动 systemd 单元误报为升级成功。
- 状态跨面板进程重启保留；新进程通过目标版本与当前版本对比确认成功。
- systemd 返回非零、任务失败或任务结束但版本未变化时，页面必须给出明确失败反馈。
- 所有命令与下载源继续固定，不接受客户端提供的命令、仓库或标签。

## 用户编辑与设备告警

- 管理员可在弹窗选择单个用户并修改设备限制和总流量限制。
- 请求必须通过会话、CSRF、范围校验和 `generation` 乐观锁。
- 保存后保留用户名、token、流量统计和节点链接身份；仅递增配置版本。
- 当 Hysteria `/online` 返回的客户端实例数严格大于设备限制时，用户名使用红色视觉告警，同时显示非颜色文字提示。
- “设备”在界面与文档中明确为在线客户端实例估算；硬件级识别只能由受控客户端提供稳定设备 ID，当前通用节点链接不具备该能力。

## 服务器重启

- 重启入口位于系统资源模块右上角，提交前显示明确确认提示。
- 仅允许登录管理员携带有效 CSRF 发起请求。
- 后端只运行固定的 `systemctl --no-block reboot`，不接收任何命令参数，并写入审计记录。
- 页面提示连接将中断；生产验收不为测试按钮而主动重启服务器。

## 验收

- 新增测试先失败，再完成最小实现。
- 全部 Python 测试、语法、ShellCheck、Ruff、Bandit 和秘密扫描通过。
- 在真实浏览器检查更新反馈、编辑弹窗、超限告警、重启按钮和移动端布局。
- 发布后在两台服务器验证版本、服务、用户数量、旧节点握手和网页/视频线路。

# 规格：分流节点 DNS 准入第五阶段

> 公开版本中的域名和 IP 是示例值；`.201`、`.210` 等尾号仅保留为节点代号。

## 目标

在数据节点已完成正式版本部署、身份摘要核对和真实直连 Hysteria 灰度后，把
`203.0.113.20` 作为 `vpn.example.com` 的第二个仅 DNS A 记录加入解析，并验证现有
用户无需更换链接、token、SNI 或证书指纹即可使用两台服务器。中央面板继续作为用户
认证、设备限制和累计流量的唯一权威。

## 不可变边界

1. 永远不生成、续签、替换、转换或重新编码 Hysteria `server.crt` / `server.key`。
2. 永远不改变 `vpn.example.com`、现有用户 URI、token 派生、HMAC 或证书指纹。
3. 面板 Let’s Encrypt 身份与 Hysteria 身份继续完全分离。
4. 数据节点不保存用户数据库、HMAC 或离线认证副本。
5. 一键部署和面板按钮都不调用 DNS 提供商 API；DNS 变更是带独立回滚的外部运维动作。

## 准入状态机

```text
direct_canary_passed
  -> 外部添加第二 A 记录
  -> 真实 DNS/数据通道验收
  -> 管理员记录 dns_admitted
  -> 外部移除第二 A 记录（回滚）
  -> 管理员记录 direct_canary_passed
```

面板记录准入时要求节点仍为已验证、`protocol_ready`，且心跳、在线快照和流量 ACK
全部位于 45 秒新鲜窗口。准入和撤出均要求登录会话及 CSRF，并写入独立审计事件。
撤出记录不要求节点在线，确保故障节点始终可从准入状态回滚。

## DNS 执行规范

- 保留现有 `.201` A 记录，只新增 `.210` A 记录；两条记录都必须为 DNS-only，不能
  使用 Cloudflare HTTP 代理承载 Hysteria UDP。
- 变更前记录现有记录 ID、内容、代理状态和 TTL；回滚只删除 `.210`，不得改写 `.201`。
- 普通 DNS 多 A 记录受客户端和递归解析器缓存影响，只提供分布，不承诺严格轮询、
  权重或主动健康检查。单节点故障时应先撤出故障 A 记录。
- 在不同递归解析器确认两条 A 记录后，才允许记录 `dns_admitted`。

## 真实验收矩阵

1. 直连 `.210:19999`，保持 `vpn.example.com` SNI、现有 token 和现有证书 pin，代理请求
   成功且出口为 `.210`。
2. 同一用户分别连接 `.201` 与 `.210`，中央在线设备数按 Hysteria 客户端实例合并；
   达到设备上限后的下一次新认证失败关闭，不踢掉既有连接。
3. 仅经 `.210` 产生一段可识别的小流量，中央累计值只增加一次；重放相同 batch 不
   重复计量，节点 spool 仅在中央 ACK 后删除。
4. 暂停 `.210` 控制面访问时，新认证失败关闭，已建立 Hysteria 会话继续传输；恢复后
   新快照和流量检查点重新建立，认证恢复。
5. 禁用测试用户或轮换测试 token 时，中央固定 `KICK_USERS` 指令只影响目标用户并在
   数据节点确认；测试完成后恢复临时用户状态，不修改现有用户链接。
6. 外部 DNS 返回 `.201` 与 `.210`，重复真实连接能观察到两台服务器；结果按 DNS
   缓存语义记录，不把每次严格交替作为成功条件。

## 回滚与完成标准

任一身份、认证、设备、计量、FULL 出站、控制面故障或真实代理检查失败，都先从 DNS
删除 `.210`，保留 `.201`，再记录撤出；不得通过放宽认证、复制用户库或替换证书绕过。
只有代码门禁、正式签名 Release、两台生产升级、DNS 外部变更和上述真实验收分别有
证据时，第五阶段才算完成。

# v0.19.0 用户节点二维码规格

日期：2026-08-16（Asia/Shanghai）

## 目标

在“用户管理”的每个用户节点操作区增加“二维码”按钮。管理员点击后，面板按需恢复现有 Hysteria 2 分享 URI，在弹窗中显示可扫描的二维码，并允许保存为 PNG。

## 行为与兼容边界

1. 二维码编码内容必须与该用户现有“分享”功能返回的完整 `hysteria2://` URI 完全一致，不修改 token、域名、端口、证书指纹、节点名或数据库结构。
2. 初始控制台 HTML 不得包含任何用户 URI、token 或二维码矩阵；仅在已认证管理员点击后，通过现有 `/users/{id}/share` POST 接口按需获取。
3. 请求继续强制校验登录会话、CSRF token 和用户 `generation`；旧版本不可恢复密钥的用户继续返回 409，并要求先轮换。
4. 普通“分享”请求保持现有 `{name, uri}` JSON 契约；只有显式提交 `qr=1` 时才额外返回二维码矩阵。
5. 二维码在服务端由内置的、MIT 许可的纯 Python 编码器生成，浏览器只用 Canvas 绘制。禁止调用外部二维码服务，禁止放宽 CSP。
6. 二维码数据限制为 21–177 的正方形 `0/1` 行矩阵；客户端在绘制前再次校验结构，并添加四模块白色静区。
7. 弹窗使用原生 `dialog`，提供关闭、复制 URI、保存 PNG 三项操作；二维码 Canvas 带可访问名称。保存文件名固定为 `hysteria2-node-qr.png`，避免将用户名带入文件路径。
8. 桌面端每行容纳六个用户操作；不超过 640px 的页面将操作区改为两行三列，弹窗宽度、二维码尺寸和高度必须适配手机视口。

## 发布与部署验收

- 版本按兼容的新增功能升级为 `0.19.0`，同步面板版本、安装器固定哈希、README、CHANGELOG 与安装器契约测试。
- 全量单元、HTTP、安装器、静态安全与语法检查通过。
- 真实桌面与手机视口完成：打开弹窗、二维码显示、复制、PNG 下载、关闭后仍停留当前筛选页。
- 发布后滚动升级三台服务器；每台升级前备份，升级后验证 systemd、HTTP 登录页、版本、数据库 `quick_check`、UDP 监听与现有用户身份摘要，再继续下一台。

## 非目标

- 不增加公开 GET 二维码接口，不把分享 URI写入 URL。
- 不改变用户创建、轮换、备份格式或 Hysteria 客户端配置格式。
- 不提供外部二维码美化、Logo 或统计追踪。

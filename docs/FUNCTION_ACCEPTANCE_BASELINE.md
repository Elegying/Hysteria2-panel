# 项目功能统计与新部署验收基线

本文把 Hysteria2-panel 当前正式版整理成可重复执行的验收合同。以后完成新部署、迁移、升级或扩容后，可以按稳定编号逐项核查，而不是只确认“页面能打开”或“服务已启动”。

## 基线与统计口径

| 项目 | 当前基线 |
|---|---|
| 面板正式版 | `v0.39.17` |
| Android App | `v0.3.6+15` |
| Git 提交 | 以正式标签 `v0.39.17` 所指提交为准 |
| Android 包名 / ABI | `vip.ssrvpn.hysteria2manager` / `arm64-v8a` |
| 功能验收点 | **178 项** |

这里统计的是可独立判断“通过、失败或不适用”的验收点，不等于源码函数数量。本文定义验收合同，不表示每次部署已经通过全部项目；旧生命周期标为兼容的条目不属于当前一键对接必经步骤。标为条件能力的项目仍需要对应基础设施，例如 HTTPS 域名、远程节点、WebDAV 或 Android 手机。

验收结论只使用四种状态：

- `通过`：达到预期结果并保留证据；
- `失败`：功能适用，但结果不符合预期；
- `未测`：尚未取得足够证据，不能用“看起来正常”代替；
- `不适用`：当前部署明确不启用该能力，并记录原因。

适用范围：`核心`=每个中央面板；`HTTPS`=默认 HTTPS 部署；`多节点`=独立数据节点；`WebDAV`=异地备份；`Android`=官方 App；`发布`=维护正式版本。

> 删除用户、重置流量、恢复备份、更新、重启服务器、紧急停用节点和切换出站策略都会改变状态。新部署应优先使用测试账号、测试节点和可回滚窗口；没有明确授权时只做只读核查。

## 新部署验收顺序

### A. 记录版本和部署形态

1. 记录面板版本、正式标签/提交、安装时间、Linux、架构、Python；
2. 记录 HTTP/HTTPS、UDP 443、远程节点、WebDAV、Android 是否启用；
3. 只记录域名类别和端口用途，不记录密码、URI、token、私钥、Cookie 或备份内容；
4. 不适用项必须写原因，不能直接算通过。

### B. 只读基础巡检

```bash
systemctl status \
  hysteria2-panel \
  hysteria2-panel-server \
  hysteria2-panel-server-443 \
  hysteria2-panel-tcp-probe \
  hysteria2-panel-tcp-probe-443

curl --fail --silent --show-error http://127.0.0.1:19998/healthz
curl --fail --silent --show-error http://127.0.0.1:19998/readyz
curl --fail --silent --show-error http://127.0.0.1:19998/metrics
```

HTTPS 部署使用真实面板域名，通过 `curl --resolve panel.example.com:19998:127.0.0.1 https://panel.example.com:19998/readyz` 固定回环连接并验证证书，替换为实际域名和端口。自签测试环境指定受信 CA，不关闭 TLS 校验。

### C. 网页和测试用户

1. 检查控制台全部卡片、桌面/手机布局和自动刷新；
2. 创建明确命名的临时测试用户；
3. 验证搜索、筛选、排序、编辑、分享、二维码、启停、改密、单用户重置；
4. 用真实客户端验证主入口和账号授权/未授权 UDP 443；
5. 验证在线数、用户总流量、来源流量和预算增量；
6. 删除测试用户并确认旧配置失效。

### D. Android App

1. 清除旧数据，确认没有预填私人面板入口；
2. 用新部署地址、端口、管理员账号登录；
3. 核对首页、用户、节点、设置与网页数据；
4. 验证用户操作、单用户/全局 TOP10、节点详情、5 秒速率；
5. 滚到每页底部，确认底栏不遮挡并避开圆角；
6. 验证主题持久化、检查更新和退出清会话。

### E. 多节点

1. 全新测试节点完成短时对接和自动身份绑定；
2. 等待六服务、双入口真实灰度和 bootstrap ACK；
3. 提前设置 DNS；当前流程不等待旧 DNS 准入；
4. 同一测试用户跨本机/远端验证统一设备和流量限制；
5. 暂停中央连接，验证既有会话、失败关闭、spool、恢复重放和幂等；
6. 在测试节点验证“一键断连→重新对接”，以及失联节点“删除对接”的不同边界。

### F. 备份与恢复

1. 下载完整备份，离线核对五成员、清单和保管方式；
2. 在隔离服务器以匹配的用户域名/端口恢复；
3. 验证目标管理员保留，源用户/流量/证书恢复且目标机器预算保留，目标临时用户移除；
4. 使用恢复后的旧 URI 做真实连接；
5. 如启用 WebDAV，手工运行一次并验证原子上传/状态；
6. 不要等生产故障才第一次测试恢复。

### G. 更新、重启和破坏性动作

默认只读。只有具备完整备份、回滚路径、维护窗口和明确授权时才执行更新、切换策略、重启、全局重置、紧急停用或生产恢复。之后必须重做阶段 B、真实握手、身份/数据比较和事务标记检查，不能只看退出码。

## 明确不属于项目功能

- 不自动修改云厂商安全组；
- 不持有、添加或删除托管 DNS；
- 不提供任意 shell、任意 systemd unit 或通用 root API；
- 不提供开放 CORS 的第三方万能管理 API；
- 不识别物理设备，只统计 Hysteria 客户端实例；
- 不把 TCP 探针或 ICMP ping 当作 UDP/QUIC 可用性；
- 不自动轮换 Hysteria 长期证书，因为旧 URI 固定其指纹；
- 不保存完整访问日志、URL、Cookie 或请求内容；域名 TOP10 是近似聚合；
- 不把用户数据中转到中央面板，客户端直连本机或数据节点；
- 不保证 32 位 ARM、x86 Android 手机/模拟器，正式 APK 只发 `arm64-v8a`。

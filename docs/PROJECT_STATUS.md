## 项目目标

为自建 Hysteria 2 的个人和小团队提供一个轻量管理面板，集中管理用户、设备上限、流量额度、节点和订阅。支持单机部署及多机扩容，用户流量直接走目标节点。升级和迁移时尽量让用户继续使用原有订阅，并确保既有用量和额度可恢复。

## 已确定的方案

- **部署与节点管理**。面板使用 Python 标准库，在 systemd Linux 上运行，默认启用 HTTPS。可使用面板本机节点，也可用短时签名命令接入远端节点。面板集中鉴权并汇总用量，节点直接承载流量。见[架构说明](ARCHITECTURE.md)。
- **账号、计量与订阅**。普通和专线账号按节点类型隔离。用户累计流量与机器预算分别记录。订阅链接采用稳定身份，显式重置订阅时同时轮换链接和节点密码。外部 AnyTLS 用于专线订阅分发，凭据加密，管理操作限管理员。见[使用指南](USER_GUIDE.md)和[变更日志](../CHANGELOG.md)。
- **备份与恢复**。格式 3 保存用户、累计用量、订阅身份及本机节点证书、私钥和端口跳跃设置。保持原订阅入口、本机代理地址和 UDP 端口时，普通用户可沿用已下发的本机节点配置。远端节点需要重新对接。恢复会保留目标面板已有的外部 AnyTLS 节点并重新加密其凭据，来源面板的外部节点需在新面板重新配置。见[备份与迁移](BACKUP_AND_MIGRATION.md)。
- **发布与升级**。正式更新走固定来源，校验 SHA-256 和 Sigstore 发布身份。多节点部署按发布手册分批升级并验证回滚路径。见[发布与回滚](DEPLOYMENT.md)。

## 接下来要做什么

1. 核对最新正式发布、生产部署版本和当前提交的 CI 结果，按[功能验收基线](FUNCTION_ACCEPTANCE_BASELINE.md)确认待验收范围。
2. 在隔离环境演练从正式版本升级和格式 3 恢复。用已下发的订阅及节点配置验证普通用户本机连接，验证目标已有的 AnyTLS 节点在恢复后仍可分发给专线用户，并检查累计用量、额度和普通用户隔离。重新对接远端节点后，通过原订阅链接验证节点刷新。
3. 验收通过后，按[发布与回滚](DEPLOYMENT.md)生成签名版本并分批升级。升级后重新导出格式 3 备份，记录实际部署版本和验收结果。

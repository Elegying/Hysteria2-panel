# 客户端本人用量接口 v1

架构决定见 [ADR-020](decisions/ADR-020-account-usage-read-api.md)。

本接口面向 SSRVPN Android、Windows、macOS 等客户端。只读当前节点密码对应账号的流量与在线客户端实例数；无需更新节点 URI、密码、认证 HMAC、QUIC 参数或节点证书。旧客户端不调用本接口，连接行为保持原样。

## 地址与认证

```http
GET /api/v1/user/usage HTTP/1.1
Authorization: Bearer <运行时从既有节点取得的认证密钥>
```

- 地址来自受信任配置中的中央面板 HTTPS 地址，不能从旧 URI 推导。
- Bearer 使用原节点密码，不是管理员 token、统计 secret 或节点机器凭据。
- 每次请求重新计算现有 HMAC 指纹并查找账号；不存明文密码，不缓存身份授权。流量用尽、设备达到上限、账号停用仍可查询；删除或轮换后，后续查询立即拒绝旧密码。已开始的并发请求以其只读事务快照为准。
- 不接受查询参数（包括用户名、用户 ID、token），不接受请求体、重复 Authorization 或分块请求体。客户端不能切换统计对象；Cookie 不赋予此接口任何权限。
- 仅接收实际 TLS 连接，明文 HTTP 返回 403，不重定向携带凭据的请求。客户端必须验证 HTTPS 主机名及证书，禁止忽略 TLS 错误或跟随重定向转发密码。
- 响应均为 JSON，包含 `Cache-Control: no-store`。不提供跨域浏览器授权。访问日志仅记录固定接口路径，不记录请求头、查询串或错误中的密钥。

## 成功响应

```json
{
  "apiVersion": 1,
  "data": {
    "scope": "account",
    "usedBytes": 0,
    "trafficLimitBytes": 268435456000,
    "onlineDevices": 0,
    "deviceLimit": 3
  },
  "meta": {
    "serverTime": 1788652800,
    "trafficObservedAt": 1788652795,
    "onlineObservedAt": 1788652798,
    "expiresAt": 1788652825,
    "complete": true
  }
}
```

上述数值为合成示例，不是任何线上账号的用量。可直接用于客户端解码测试的零值、超额和失败样例见 [JSON 样例集](examples/client-usage-v1.json)。

| 字段 | 语义 |
|---|---|
| `apiVersion` | 整数 1 |
| `data.scope` | 固定字符串 `account` |
| `usedBytes` | `proxy_users.tx_bytes + rx_bytes`，即现有账号已结算总账；包含各客户端、各受管节点及历史来源，沿用管理员单用户/全局重置规则 |
| `trafficLimitBytes` | 现有账号流量额度 |
| `onlineDevices` | 本机统计入口及当前受管远程节点的该账号客户端实例数相加；不去重物理设备，也不是代理 TCP/UDP 流数量 |
| `deviceLimit` | 现有账号客户端实例上限 |
| `serverTime` | 生成响应时的 Unix 秒 |
| `trafficObservedAt` | 各必需来源已结算采集时间的最小值 |
| `onlineObservedAt` | 各必需来源在线采集时间的最小值 |
| `expiresAt` | 所有参与校验的采集/确认时间中的最小值加 30 秒；请求不会刷新它 |
| `complete` | 仅在所有必需来源都可确认且仍有效时返回 `true` |

计数及时间均为非负 JSON 整数。有效零值返回 200；超额、超设备数返回真实值，不截断。客户端应支持至少 64 位计数，不要使用 32 位整数。

“完整”指上述采集时刻的完整快照，并不承诺请求瞬间的连接数或尚未上报的字节。意外断网可能等待 QUIC 超时才从 Hysteria 在线数中消失。

## 采集、来源与失效

查询不调用 Hysteria `/traffic?clear=1`、`/online`、`/kick`，不调用管理操作或远程节点，不创建租约，不修改账号、流量、配置或业务审计表。请求只读取已有总账、缓存及数据库快照。

- **本机**：复用 `UsageManager.collect_once()` 的既有后台结算与在线核对，默认每轮完成后等待 10 秒。仅成功结算并读取全部本机统计入口后，发布内存快照；记录实际采集开始时间。空采集也产生有效检查点。主入口/额外入口部分失败、在线采集失败或结算失败会使该查询快照失效。服务重启后在首次成功后台轮次前返回 503。认证或管理员查询不会替代这个后台轮次为用户接口续期。
- **远端**：复用既有签名流量批次和在线快照。新增运行态表 `node_usage_checkpoints(node_id, traffic_observed_at, online_sequence)`。每个成功提交的新批次（包括空批次）在同一事务中记录批次原始 `observedAt`，并清除在线确认序号；后续成功接受在线快照后记录对应序号。未完成的上传、缺少在线确认、旧采样迟到均不会被当成完整的新数据。非空重复批次的幂等返回不续期；空批次即便重传也只保留原采集时间。
- **范围**：本机为必需来源；远端沿用面板活动来源过滤，排除 revoked、stopped、archived 节点。活动来源存在 standby、未就绪或缺少检查点时，整个接口保守返回 503。退役来源的历史流量仍在账号总账内，在线数不继续计入。
- **时效**：本机和远端时间必须非负、不在中央时钟未来且未满 30 秒；远端还核验在线序号、在线采集时间、流量 ACK 和接收时间。远端未传来显式故障时，最后一次完整快照可在剩余有效期内使用，超时后立即 503。中央与节点应同步系统时钟；本接口对未来时间保守拒绝，不沿用代理认证的时钟容差放宽。
- **账本口径**：`usage_origin_users` 是来源明细，`proxy_users` 是已有配额总账；查询复用后者，不重复将两张表累加。用户长时间无新增流量、甚至没有来源明细行，不等于采集失败；不使用用户 `updated_at` 判断新鲜度。
- **重启/备份**：本机快照只驻内存；新表在 runtime epoch 清空，并列入可移植备份的运行态清理名单，不恢复过往“在线”证据。新增表兼容旧数据库，不重建用户身份或业务账本。

## 错误与边界

```json
{"apiVersion":1,"error":{"code":"STATS_STALE"}}
```

失败时没有 `data`、部分用量或伪造零值。

| HTTP | 稳定代码 | 客户端处理 |
|---|---|---|
| 400 | `INVALID_REQUEST` | 修正 URL、请求体或头部，不重试原请求 |
| 401 | `INVALID_CREDENTIALS` | 密码无效/已删除/已轮换；停止自动轮询，不影响本地已有节点的保存 |
| 403 | `HTTPS_REQUIRED` | 修正受信任服务配置，禁止降级 HTTP |
| 405 | `METHOD_NOT_ALLOWED` | 只允许 GET |
| 413 | `REQUEST_TOO_LARGE` | 缩小请求 |
| 429 | `RATE_LIMITED` | 遵守整数秒 `Retry-After`，随机退避 |
| 431 等 HTTP 解析错误 | `INVALID_REQUEST` | 修正非法或过大的 HTTP 头部 |
| 503 | `STATS_UNAVAILABLE` | 本机未采集、采集/数据库故障或时间异常 |
| 503 | `STATS_INCOMPLETE` | 参与来源缺失、未就绪或尚未确认完整快照 |
| 503 | `STATS_STALE` | 至少一个来源已到期 |

限制独立于代理认证/管理员登录限流：每凭据 12 次/60 秒、每来源 IP 120 次/60 秒、接口总计 600 次/60 秒；IPv6 以 /64 归组。限流表最多 4096 项，满表不驱逐尚有效的限额。最多 8 个接口 HTTP 请求同时处理，其中最多 4 个执行数据库查询；多余请求立即 429。不要通过换密码或并发请求规避限制。

已识别的接口请求总期限 3 秒、套接字空闲期限 2 秒，URL 最长 1024 字符、解析后头部总长不超过 8192 字符，禁止请求体。数据库使用 `mode=ro`、`query_only`、100 毫秒锁等待及约 200 毫秒 SQLite VM 处理期限；不等待采集互斥锁。TLS 握手/尚未给出请求行的连接沿用原服务器有界 worker 与期限，公网仍应使用已有连接层容量防护。极慢连接、TLS 失败及整个监听器饱和可能直接断开，客户端必须处理传输失败，不能假定总能收到 JSON。

客户端建议前台每 10 秒查询一次、同一账号合并并发，后台暂停；429 按响应退避，503 显示“暂不可用”。依据 `expiresAt - serverTime` 设置单调时钟倒计时，旧缓存不可继续显示为当前有效用量，不要把失败转为零。

## 旧链接不变：服务配置与可信绑定

服务端沿用现有独立面板 HTTPS 配置：`HY2PANEL_PANEL_SCHEME=https`、`HY2PANEL_PANEL_PUBLIC_HOST`、`HY2PANEL_PANEL_PORT`、`HY2PANEL_PANEL_TLS_CERT`、`HY2PANEL_PANEL_TLS_KEY`。安装器对应使用现有面板域名/证书流程，见 [部署文档](DEPLOYMENT.md)。接口与管理面板同一 HTTPS 监听器，但身份域和权限完全独立；不向普通用户授予其他路由的权限。HTTP 后端仅凭 `X-Forwarded-Proto` 不会启用此接口，TLS 必须到达面板。

SSRVPN 需要在**节点 URI 之外**注入服务目录和节点绑定。以下是待客户端实现消费的配置格式示例，不是已内置于 SSRVPN 的功能，也不由本接口接收：

```json
{
  "configVersion": 1,
  "usageServices": [
    {
      "id": "managed-account-service",
      "baseUrl": "https://usage.example.test:19998"
    }
  ],
  "nodeUsageBindings": [
    {
      "protocol": "hysteria2",
      "host": "node-a.example.test",
      "port": 443,
      "pinSHA256": "<原节点的完整证书指纹>",
      "usageServiceId": "managed-account-service"
    }
  ]
}
```

接入方必须落实以下过程：

1. 运营方确认每个自有节点属于哪个账号服务，发布经审核的精确绑定。匹配规范化后的协议、节点主机、端口及原有证书身份；若原配置含 SNI，也应绑定并校验 SNI。禁止用节点名称、包含“私家车”等字样、IP 段猜测或端口扫描建立信任。
2. Android、Windows、macOS 共享同一份经审核的配置，可随应用打包注入；若后续使用远程配置，必须验证独立的签名与版本、防回退。用户也可在明确确认运营方/服务证书后手工绑定。配置不包含密码；未匹配时隐藏查询入口或显示“未配置”，原连接照常工作。
3. 客户端验证 `baseUrl` 为固定 HTTPS origin，无 userinfo、query、fragment 或任意路径；固定拼接 `/api/v1/user/usage`。不从不可信订阅文本接受密码接收地址，不发送到猜测地址。
4. 仅在绑定成功后，从已有节点的安全存储/URI 解析结果提取原密码，在内存生成 Authorization 头。不要落日志、复制到 URL、遥测或崩溃报告。切换账号/节点时取消旧请求，按“受信任服务 ID + 凭据身份”隔离缓存，禁止后到响应覆盖其他账号。
5. 查询服务使用独立 HTTPS 证书验证。旧节点的 `insecure=1`、`pinSHA256` 是 Hysteria 连接参数，不能用于关闭查询服务 TLS 验证，也不能假定查询服务与节点共用证书。
6. 展示账号范围数据；不将多个节点返回的同一账号结果再次相加，不将实例数标为去重物理设备数。

本仓库完成服务端与配置接入契约。SSRVPN 跨平台代码、服务目录加载器和真实客户端画面不在本次面板仓库变更内，尚未声明完成客户端发版或生产联通。

## 验证、部署与回滚

专项命令：

```bash
python3 -m unittest tests.test_user_usage_api -v
```

测试启动真实本地 HTTPS 服务，使用临时数据库、随机生成的旧式密码及合成统计源，覆盖账号隔离、零值、超额、停用、轮换删除、跨节点账本、采集失败、过期、并发、慢头部、数据库期限和业务状态不变。模拟统计和本机 TLS 结果不等同生产节点联通。

部署前仍需提供：实际中央 HTTPS origin（含端口）、有效证书/信任链、精确自有节点绑定清单及证书身份、SSRVPN 可信配置注入位置和版本、各节点版本/时钟/采集健康状态。本文的 `.example.test` 地址不能用于生产。

后续获得独立发布/部署授权后，按既有受保护 PR、CI、固定哈希安装器、签名发布和事务更新流程操作；先保留正常备份及更新器回滚材料。无需轮换账号或修改节点链接。更新后先检查服务、数据库、采集及节点控制健康，再使用授权的既有测试账号通过真实 HTTPS 只读查询；不通过重置生产流量做验收。

回滚优先使用现有更新器事务保留的安装前文件及备份，按 [部署与回滚契约](DEPLOYMENT.md) 操作。新增表仅为运行态，旧程序不引用它，不需删除表或回滚账号账本；回滚后客户端应将接口缺失视为不可用，继续原有代理连接。发布与生产部署必须按上述门禁及授权流程执行。

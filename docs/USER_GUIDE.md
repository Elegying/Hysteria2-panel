# 使用指南

这份文档解释面板中最常用的操作和术语。所有按钮都只影响本项目管理的用户、节点和服务，不提供任意 shell 或通用服务器控制能力。

## 认识控制台

控制台分为五类信息：

1. **顶部状态**：Hysteria 是否运行、最近刷新时间和当前用户数；
2. **全局统计**：在线设备、上传、下载和总流量；
3. **服务与系统**：启停 Hysteria、切换出站策略、查看资源和更新版本；
4. **节点统计**：按面板本机与数据节点拆分流量、设备和预算；
5. **用户管理**：搜索、筛选、排序及六个直接操作。

页面数据会自动刷新。网络暂时异常时，界面会保留最后一次可信结果，并在后续刷新中重试。

## 管理用户

### 创建用户

点击“添加用户”，填写：

- 用户名；
- 客户端实例上限，默认 3；
- 总流量上限，默认 250 GiB；
- 是否允许账号使用 UDP `443`。

创建后会显示一次连接凭据和 Hysteria URI。请立即复制到安全位置，避免通过聊天群、公开 Issue 或截图传播。

### 六个用户操作

| 操作 | 结果 |
|---|---|
| 分享 | 显示并复制当前 Hysteria URI |
| 二维码 | 生成当前 URI 的二维码，可保存为 PNG |
| 禁用 / 启用 | 拒绝或恢复新认证；禁用时会请求断开现有连接 |
| 改密 | 轮换认证密钥，旧配置失效，需要重新分享 |
| 重置 | 把该用户累计流量归零，并请求断开旧连接 |
| 删除 | 删除用户并请求断开连接，操作不可由面板撤销 |

编辑用户的设备、流量或 UDP `443` 权限不会改变现有 URI。只有“改密”会更换认证凭据。

### “设备数”实际代表什么

设备限制统计的是 Hysteria `/online` 返回的**客户端实例数**，不是物理手机或电脑数量。

- 同一个网关后的多台终端可能只表现为一个实例；
- 同一设备同时运行多个核心或频繁重连，可能产生多个实例；
- 达到上限后，已有实例继续使用，新实例认证失败；
- 面板不会为了接纳新实例而自动踢掉最早的连接。

因此，“3 台设备”应理解为“最多 3 个同时在线的 Hysteria 客户端实例”。

### UDP `443` 权限

默认账号只使用主 UDP 端口。为账号开启 UDP `443` 后：

- 原 URI 和主端口继续有效；
- 如客户端需要走 `443`，复制原配置并只修改服务器端口；
- 两个入口共用 token、证书、设备数和流量额度；
- 未获准账号从 UDP `443` 认证会失败。

TCP `443` 探测成功不代表账号拥有 UDP `443` 权限。

## 搜索、筛选和统计

用户列表支持：

- 按用户名即时搜索；
- 按启用状态、在线状态和 UDP `443` 权限组合筛选；
- 按在线客户端实例数或总流量排序；
- 查看单个用户的当前流量、额度进度和超限提示。

“分机器流量”是 Hysteria 已结算的用户上传与下载，不等同于云厂商账单或网卡总流量。升级前无法可靠归属到机器的累计值会显示为“升级前历史（未归属）”，管理员可以单独删除这部分拆分记录，但不会改变用户总流量。

## 机器预算

面板本机和每个数据节点都可以设置：

- 月流量预算；
- 当前周期已用流量基线；
- 告警百分比；
- 每月 UTC 重置日。

保存预算时会锁定当前账本，之后只增加新流量。设置为 `0 GiB` 表示关闭该机器预算。预算是运营提示和节点生命周期依据，不会替代用户级总流量限制。

## 接入数据节点

### 全新节点

1. 打开“对接节点”；
2. 选择“全新节点对接”并生成短时命令；
3. 在空白数据节点上以 root 执行；
4. 回到面板，逐字核对双方显示的 16 位 Ed25519 指纹短码；
5. 确认后等待 Agent 自动部署、验收主入口和 UDP `443`；
6. 验收完成后，手工把 `PUBLIC_HOST` 的 A/AAAA 加入该节点公网 IP；
7. 等待面板只读检查 DNS 并自动准入。

面板不会持有 DNS 凭据，也不会替你添加或删除记录。云安全组仍需人工配置。

### 安全重绑定

“安全重绑定”只用于**同一台已经部署的数据节点**重新连接中央面板。它保留：

- Ed25519 私钥与公钥；
- Hysteria 证书和私钥；
- 运行中的数据面与已有会话；
- durable traffic spool。

它不负责把旧机器的身份隔空迁移到空白新服务器。换机应使用“全新节点对接”，通过验收并加入 DNS 后再停用旧节点。

## 摘流、停用和恢复节点

计划换机或节点流量将耗尽时：

1. 点击“开始摘流”，节点继续服务已有流量；
2. 手工从 `PUBLIC_HOST` 的 DNS 删除旧节点 IP；
3. 等待 TTL 生效和在线设备归零；
4. 点击“检查并安全停用”；
5. 面板核对 DNS、在线快照和流量 ACK 后，才会下发固定停止命令。

“紧急停用”会跳过 DNS 与设备门禁。旧 DNS 仍命中时，用户会直接连接失败，只应在明确的安全事件或严重故障中使用。

停用不会删除 Agent、节点私钥或流量 spool。恢复节点后，需要重新把 IP 加回 DNS，并等待只读准入检查通过。

## 出站策略

| 模式 | 适用情况 | 重要边界 |
|---|---|---|
| `FULL` | 需要完整公网访问能力 | 允许 BT/PT、SMTP、游戏和非标准端口，滥用风险更高 |
| `WEB` | 主要用于网页、视频、DNS、NTP 和公网 SSH | 是端口/目标策略，不是 DPI，无法保证识别所有 BT/PT |

切换策略作用于整台节点上的全部账号，并会短暂重启 Hysteria、断开现有连接。它不会改变用户 URI、token、证书或指纹。

## 数据迁移和更新

- “数据迁移”可下载完整备份或上传恢复包；备份等同于节点凭据，必须安全保管；
- “检查更新”只读取正式 GitHub Release；
- “立即更新”会显示排队、运行、成功或失败，服务重启期间页面会自动重试；
- 不要在更新运行时重复提交恢复、证书续期或其他维护任务。

完整迁移流程见[备份与迁移](BACKUP_AND_MIGRATION.md)，故障处理见[运维手册](OPERATIONS.md)。

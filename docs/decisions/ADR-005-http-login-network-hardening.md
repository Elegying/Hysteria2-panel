# ADR-005：HTTP 缺省、登录锁定与双层 BBR 优化

## 状态

已接受，2026-08-11。取代 ADR-002 中关于缺省协议、UDP 缓冲和 TCP 拥塞控制的决策。

## 背景

自签名 HTTPS 会让部分浏览器和手机出现证书警告或访问障碍，因此项目需要在明确风险的前提下优先保证面板可访问性。与此同时，管理员登录必须抵抗普通密码爆破，主要代理场景是 YouTube 视频和海外网页，安装器还需要同时处理 Hysteria QUIC 隧道和服务器到源站的 TCP 出站连接。

## 决策

- 全新部署的面板缺省使用 HTTP；显式选择 HTTPS 时继续可用。这个选择只影响管理面板，Hysteria 数据通道始终使用自身 TLS 和证书固定。
- HTTP 模式继续启用 HttpOnly、SameSite=Strict、CSRF、CSP、会话撤销和通用登录错误，但无法提供传输加密、Secure Cookie 或 HSTS。文档要求把面板端口限制在可信管理来源，敏感备份只能在可信链路操作。
- 登录失败按来源 IP 使用内存滑动窗口统计：15 分钟内第 5 次错误立即锁定 15 分钟并返回 `429`/`Retry-After`；成功登录清除该来源记录。不存在的账号仍执行同等级密码派生，且记录表有固定上限。
- Hysteria 配置明确使用 `congestion.type: bbr`、`bbrProfile: standard` 和 `ignoreClientBandwidth: true`。不自动估算线路带宽，也不启用依赖准确带宽值的 Brutal。
- Linux UDP 收发缓冲上限提高到至少 16 MiB，已有更高值不降低；Hysteria 服务设置 `Nice=-5` 和高文件描述符上限。
- 内核提供 BBR 时启用 `fq` 与 Linux TCP BBR，改善服务器到以 TCP/HTTPS 提供内容的网页和视频源站连接；不支持时恢复原设置并继续部署。内核 TCP BBR 不被描述为 Hysteria UDP/QUIC 拥塞控制的替代品。
- 安装器不自动修改防火墙，不伪造 ICMP/TCP 延迟，不写入缺少官方依据的额外 sysctl。

## 备选方案

### 继续缺省使用自签名 HTTPS

传输保密性更好，但与“尽量避免 HTTPS 面板访问问题”的产品目标冲突。保留为显式选项，不再作为缺省。

### 全局账号锁定或把失败次数永久写入 SQLite

全局锁定容易被攻击者用于阻断唯一管理员，高频持久写入又会放大磁盘压力。采用按来源 IP 的有界内存状态，并把安全组来源限制作为更外层防线。

### 自动测速并启用 Brutal

错误的带宽估计会浪费带宽并降低稳定性，且共享服务器上难以可靠自动估算每条客户端线路，因此不采用。

### 写入大量通用“网络优化”参数

不同内核和云厂商的默认值、可用模块与队列规则不同，盲目覆盖风险高。只保留 Hysteria/quic-go 官方有明确依据的 UDP 缓冲与服务优先级，以及经过能力检测的 `fq`/TCP BBR。

## 后果

- 新部署更容易直接打开面板，但 HTTP 上的密码、会话和迁移 ZIP 都是明文，不能把它描述为安全链路。
- 单来源普通爆破会被锁定；分布式攻击、服务重启后的状态清空和已窃取会话不由这一机制单独解决。
- QUIC 和 TCP 出站分别获得有边界的优化；实际 YouTube 与网页体验仍取决于跨境线路、丢包、客户端、源站和云厂商限速。

# ADR 027：展示读取与同步计量隔离

日期：2026-10-24。状态：工作树实现，未发布。

隔离部署的容量基线发现，App 用户列表和网页首页调用 `snapshot()` 时会同步采集两个 Hysteria 入口，并在认证共用的互斥锁下执行。并发刷新会放大认证排队，即使没有新增流量也重复访问统计与 systemd。

网页首页和移动展示接口改用 `read_snapshot()`：实时读取已经提交的数据库行，在线状态采用后台采集器已发布的检查点；不主动采集、不获取认证/采集互斥锁。原同步 `snapshot()` 留给既有调用者，认证、额度修改、备份前结算及恢复流程不变。

独立的展示读取锁约束完整用户表的并行物化，页面和 App 复用该次查询的用户行，避免并发 SQLite 逐行读取及重复查询引起争用；它不缓存用户行，不阻塞认证互斥锁。移动会话每次仍从数据库核对凭据与过期状态，但同一秒已记录的 `last_used_at` 不重复写入；跨秒正常更新，撤销及轮换语义不变。

后台正常采集周期为 10 秒。流量与在线检查点缺失、失败、未来时间或超过 43 秒时，展示标记不可用、不完整，本机在线设备数为未知；不得把缓存伪装成当前观察结果。用户删除、权限修改及已提交的用量修改仍直接从数据库读取，不缓存账户行。展示检查点不能用作准入决定。

接口字段保持兼容，数据格式和身份不迁移。回滚只需恢复原来的展示调用及模块，不需要变更数据库。验证覆盖持锁时展示完成、读取无采集副作用、检查点失效、当前用户行、禁用后认证拒绝，并在真实部署上对比相同负载。

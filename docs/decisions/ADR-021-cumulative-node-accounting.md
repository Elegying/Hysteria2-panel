# ADR 021 节点累计流量与可恢复检查点

状态：已实现，待发布及真实 Linux 节点验收。

## 问题

Hysteria 的 `/traffic?clear=1` 在输出响应前清零。节点若因为响应超限、网络中断或解析失败拒绝它，持久化队列无法恢复已经清除的数据。仅增加读取上限会把故障移到另一个边界。

## 决策

生产节点通过 `CumulativeTrafficCollector` 读取 `/traffic` 的累计值，每个入口保留独立检查点。响应上限为 4 MiB，采样日志上限为 24 MiB；超出限制时明确失败，保留上游计数，不发送破坏性清零请求。既有面板协议、签名、1000 用户批次上限及 240 KiB 单批限制保持兼容。

以固定 Hysteria systemd 单元的 `InvocationID` 标识内核运行周期，采样前后均读取并比较。相同周期只结算计数差额；新周期从零开始；同周期计数倒退则报错，避免把外部清零误认为合法重启。标识不可用时失败关闭，不猜测周期。[systemd 官方语义](https://github.com/systemd/systemd/blob/v245/man/systemd.exec.xml#L2225-L2231)。

持久顺序为：读取累计快照 → 生成固定批次编号 → 原子写入带待落盘批次的检查点 → 写入并同步 spool → 原子清除检查点中的待落盘部分。检查点位于 spool 的同级文件 `spool.cumulative`，权限 `0600`，沿用受管状态目录。磁盘写入中断后按原批次编号恢复；即使部分批次已经上传，中央现有去重事务也不会重复累计。

采集失败仍补传已落盘批次，避免一个失败入口或满队列阻塞健康数据。此补传仅由本地采集失败触发，不重放失败的合并控制请求。检查点尚未完成时不能发布完整在线快照。重试时流量使用本次成功读取的时间；此前已采样的域名增量保留原时间，避免给故障恢复后的新流量回填旧日期。

## 兼容与边界

- 无检查点的首次启动结算上游当前未清除的计数，兼容旧代理最后一次清零后的增量。
- 停服维护使用当前已安装代理的计量契约。安装器以无凭据的 `accounting-mode` 探测识别 `cumulative-v1`；旧代理的参数解析返回 2 时，维护助手使用仅适用于 `quiesce-traffic` 的 `--legacy-traffic`。其他探测失败或未知结果拒绝结算，避免误清累计计数。
- 旧版升级在连接未排空时会恢复旧控制服务，因此成功停止旧内核之前必须沿用旧清零方式，不能提前采用非清零检查点。否则助手已经结算的计数仍留在内核里，恢复的旧代理会再次上报。成功切换后常规控制循环始终使用累计采集；不允许向 `control-once` 或 `control-loop` 传递兼容开关。
- 已采用累计采集的节点在维护失败后复用检查点；维护只包含一个入口时，保留另一入口的检查点。旧版迁移阶段仍具有原有清零响应到持久化之间的故障窗口，本决策没有将该阶段描述为累计采集的无损保证。
- 保留现有统计客户端接口供旧适配器和测试使用，生产控制入口显式注入累计采集器。
- 升级、回滚仍使用受管“结算并排空 → 停止数据面 → 替换 → 启动”流程。不能仅替换成旧代理而继续使用同一内核累计计数，否则旧代理会把已结算部分重新清零上报。
- 运行期间不要删除检查点或手工调用清零接口。检查点损坏时保留证据并对账，禁止静默从零继续。
- 累计映射包含本次内核运行周期曾出现的账号，达到容量上限后需要受管维护处理。内核被强杀前尚未采样的数据仍只在内核内存中，本协议不保证恢复这部分数据。

回归覆盖原 2,550 个长用户名场景、超限重试、部分入口失败、磁盘满、批次落盘后中断、控制进程与内核分别重启、已有批次补传、CLI 工厂实际采集路径，以及故障恢复后的观察时间。升级回归另执行真实安装器函数，覆盖旧版/新版排空失败后恢复、旧版成功切换及计量方式识别失败。

# ADR-015：可跨重启恢复的安装器升级事务

- 状态：已接受
- 日期：2026-08-20

## 背景

原安装器能捕获普通退出并回滚，但 `SIGKILL`、宿主机掉电或内核重启不会执行 shell `EXIT` trap。若中断发生在程序、配置或 systemd unit 覆盖之后，下一次开机可能启动一组混合版本文件。备份也缺少逐文件完整性证明和空间预检。

## 决定

现有受管安装升级时：

1. 在停止面板写入并完成 SQLite 检查点后创建一致性备份；
2. 用 root-only JSON 清单记录备份中每个目录、普通文件、符号链接、权限、所有者和 SHA-256；
3. 检查备份分区至少容纳当前受管程序、配置、数据库及 64 MiB 余量；
4. 安装固定的开机恢复 unit 和面板依赖 drop-in，再原子写入只包含严格备份路径的 `.upgrade-active`；
5. 只有以上状态持久化后才覆盖程序；
6. 中断恢复先验证标记、目录所有权和完整清单，再恢复文件并异步排队启动旧服务；独立复核任务确认 HTTP、认证、UDP/TCP 监听和所需 unit 后才删除标记。

任何清单、路径或健康检查异常都保留事务标记并停止自动覆盖。正常升级通过全部健康与防火墙复核后先清标记，再提交安装。

自动备份只匹配安装器生成的 `YYYYMMDDTHHMMSSZ-<8 hex>` 目录；最多保留 10 份且最长 90 天。当前升级备份和不符合该命名的手工/恢复目录不删除。

## 结果

普通错误继续同步回滚；不可捕获中断可在下次开机或人工启动恢复 unit 后收敛到完整旧版本。恢复基础设施自身保持固定、root-only 且不接受浏览器或环境提供的命令和路径。代价是升级多一次备份清单遍历、磁盘余量要求以及一个短暂的恢复后健康复核阶段。

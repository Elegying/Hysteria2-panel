# ADR-008：工作线程监督与升级失败自动回滚

## 状态

已接受，2026-08-12。

## 背景

面板进程同时承载公网管理 HTTP、回环 Hysteria 认证和流量采集。旧实现只有认证服务运行在主线程；管理 HTTP 或采集线程退出后，进程仍可能被 systemd 判断为正常运行。安装器虽然在覆盖前备份现有状态，但升级后的服务或健康检查失败时只报告错误，不会自动回到可用版本。

## 决策

- 三个长期工作线程由同一监督器启动。任一线程抛出异常或意外正常返回，监督器关闭全部本地服务并令主进程失败退出，由现有 `Restart=on-failure` 负责重启。
- 不增加第二套守护脚本、常驻 root 进程或第三方进程管理依赖；正常停机继续由 systemd 负责。
- 现有受管安装在写入前建立唯一备份。写入开始后保持回滚标记，直到面板、认证、Hysteria、TCP 探测和所有监听端口通过最终检查。
- 回滚覆盖程序、配置、TLS 身份、SQLite、systemd 单元、sudoers 和本轮修改的网络参数，并尝试启动旧服务。回滚失败时保留明确的备份目录供人工恢复。
- 全新安装没有可证明可用的旧版本，因此不伪造回滚；失败后允许安装器幂等重试。

## 后果

- 认证或管理能力的局部失联会变成可观察的进程失败和 systemd 重启，而不是长期隐藏故障。
- 升级出现语法、权限、配置或健康问题时优先恢复用户可用性和旧节点身份。
- 自动回滚不是跨主机灾备替代品；仍需保留面板生成的节点身份 ZIP 和异机恢复演练。

# ADR 022 移动会话撤销与离线恢复

状态：已实现，待发布及 Android 真机验收。

## 问题

App 重启后非当前面板没有访问令牌；访问令牌过期也无法调用原退出接口。清除本地刷新令牌后，客户端失去后续撤销依据，服务端会话可能继续有效。

## 决策

登录和刷新额外返回 `revocationToken`。它以独立用途的 HMAC 绑定随机会话 ID，刷新时不变，无需新增数据库字段。它只能删除对应移动会话，不能认证、读取数据、修改账号或签发令牌。管理员凭据变更删除会话后，该凭证失去作用；同设备重新登录创建新会话，旧撤销凭证不能影响新会话。

退出接口接受该撤销凭证，也兼容当前刷新令牌或访问令牌；只做撤销时不要求访问令牌仍有效。重复请求返回 200 与是否删除会话的布尔值，便于结果未知时重试。

App 在同一个安全存储文档中原子保存“清除登录状态”和“待撤销凭证”。保存失败则保留原登录，不提前撤销。队列最多 32 项，成功确认后清除，离线时按原面板退避重试，重启后继续。队列不保存密码，也不作为可恢复登录使用；后台清理只更新队列字段，避免覆盖并发登录或切换后的面板信息。

本地退出提交期间保留操作锁，重复退出共享同一个提交 Future；新登录等待本地提交结束。共享 Future 在安全存储提交结束时释放，远端撤销仍按原队列执行。这样不会因新一轮登录代际跳过排队中的退出，也不会让较早退出的网络等待替代后续会话的本地退出。

登录前为失败清理检查队列容量，满 32 项时不向服务端签发新会话。已签发但未安装到当前状态的会话，在所有异常路径统一尝试撤销并保留可用的重试依据。

## 兼容与验证

旧 App 忽略新增字段，Bearer 退出继续可用。新 App 对旧面板保留刷新后立即退出的兼容路径；访问和刷新凭证都已失效、服务端明确返回 `REFRESH_EXPIRED` 且不存在稳定撤销凭证时，结束无效重试。旧服务端不提供跨刷新稳定的撤销能力，因此完整的并发保证要求服务端一并更新。

回归直接验证访问过期、非当前面板、并发刷新、重复退出、伪造撤销凭证、跨设备隔离、离线后重启重试、存储失败不撤销当前登录，以及慢存储期间退出与新登录/连续退出、撤销队列容量边界。没有把控制器测试当作 Android 系统安全存储的真机验收。

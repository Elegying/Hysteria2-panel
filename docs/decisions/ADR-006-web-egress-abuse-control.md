# ADR-006：网页/视频出站策略与 BT/PT 防滥用边界

## 状态

已接受，适用于 v0.11.0 及以后版本。

## 背景

节点主要用于 YouTube 和海外网页，同时需要降低认证用户进行 BT/PT、DHT、扫描、邮件滥发和内网探测的风险。Hysteria 2.12.1 官方 ACL 可以按目标地址、协议和端口选择 `direct` 或 `reject` 出站，但不提供加密 BitTorrent 的内容识别。

## 决策

- 安装器持久化 `HY2PANEL_EGRESS_POLICY`，合法值只有 `web` 和 `full`；缺省为 `web`，升级沿用已有值。
- `web` 先仅对 `HY2PANEL_PANEL_ACCESS_IPS` 中经过校验的精确 IP 放行当前面板 TCP 端口，再拒绝环回、RFC 1918、CGNAT、链路本地和 IPv6 ULA，随后放行网页/视频所需端口，最后 `reject(all)`。
- `HY2PANEL_PANEL_ACCESS_IPS` 最多接受 16 个 IPv4/IPv6 地址；全新安装默认使用本机检测 IP，升级沿用现有值。禁止用 `direct(all, tcp/面板端口)` 代替精确地址规则。
- `full` 不写 ACL，只作为管理员明确选择的兼容模式。
- 规则属于服务器部署策略，不写进用户数据库、迁移 ZIP 或分享 URI；恢复用户数据不会悄悄改变新服务器的出站策略。
- 文档明确端口 ACL 不是 DPI，不能保证识别伪装在允许端口或外部中继中的加密 P2P。

## 取舍

### 只封常见 BT 端口

现代客户端能随机端口，DHT/uTP 也不依赖传统 `6881-6999`，容易绕过，因此拒绝。

### 在面板中实现 DPI 或安装第三方识别组件

加密 P2P 仍可规避，且会引入高 CPU、内核兼容、隐私与供应链风险，不符合轻量、可审计设计，因此拒绝。

### 保持完整出站并只写使用条款

无法在技术上降低滥用风险，因此不作为默认值；保留 `full` 只用于管理员接受风险后的兼容需要。

## 结果

- 常规网页、HTTPS 与 HTTP/3/QUIC 保持可用，绝大多数非网页端口和普通 BT/PT 连接被阻断。
- 游戏、邮件、SSH、非标准 API 和部分实时通信在 `web` 模式下不可用，这是有意的安全边界。
- 对允许端口上的加密 P2P 只能结合流量异常、连接扇出、云厂商滥用告警和人工处置进一步降低风险，不能作绝对保证。

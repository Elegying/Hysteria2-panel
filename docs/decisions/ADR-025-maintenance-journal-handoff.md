# ADR-025：维护结算与面板日志交接

- 状态：已接受
- 日期：2026-10-10

## 背景

出站策略切换必须先排空连接、结算流量，再重启代理入口。它通过独立采集锁与面板串行执行，面板进程本身仍然存活。如果维护任务已经提交面板的旧批次，随后采集的新批次却未能写入数据库，磁盘日志会属于新批次，而面板内存仍缓存旧批次，或仍认为没有待入账数据。

仅有文件锁不能解决释放锁之后的缓存失效。旧实现无条件删除待入账文件，或者直接用新采样覆盖文件，会使维护留下的流量丢失。每日异地备份已经按 [ADR 024](ADR-024-offsite-backup-accounting-isolation.md)使用已提交快照；必要维护结算仍需要明确的交接规则。

## 决定

1. 继续使用现有采集锁、单个 `pending-traffic.json` 和数据库批次幂等性，不增加服务或日志格式。
2. 采集器先提交自己持有的内存批次。清理时重新读取磁盘，只删除批次编号与自己一致的日志。
3. 内存批次完成后，重新读取磁盘日志并继续重放，直到没有待处理日志，才开始新的清零采样。存活面板与新建采集器遵守同一规则。
4. 重放、校验或清理失败时中止本次采集，保留内存及尚存的日志供下次重试。提交后清理前重启依靠原有批次编号去重。
5. 从磁盘接管的记录保持原有采样时间和恢复语义，不把它当作与当前人工调整有明确先后关系的新鲜本机样本。

## 后果与边界

- 保持用户总账、机器来源、域名记录、月初重置、文件权限和备份格式兼容；已有维护锁与认证门禁继续生效。
- 修复覆盖实际 `apply-egress-policy` 入口、真实文件锁、SQLite 事务和待入账文件，包含空缓存、旧缓存、连续数据库失败、提交后重启及损坏日志。
- 调用者仍须遵守现有协调方式：出站切换持采集排他锁，安装和恢复先停止面板写入。这个交接规则不使任意并行启动的 `sync-traffic` 命令成为受支持用法。
- 本机原有清零采样在首次获得响应与首次持久化之间仍有故障窗口；本决定处理已形成批次的交接，不代表消除了所有断电丢失风险。
- 每日异地备份保持 ADR 024 的只读已提交快照策略，不因支持维护交接而重新引入额外采集器。

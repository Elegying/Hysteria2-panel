# ADR-016：新装 HTTPS 缺省与在线更新目标固定

## 状态

已接受，2026-08-28。取代 ADR-005 的全新安装缺省 HTTP 决定，不改变历史安装和 Hysteria 客户端身份契约。

## 背景

公网 HTTP 管理面会明文传输管理员密码、会话 Cookie 和迁移备份。与此同时，自动把历史 HTTP 安装迁移到 HTTPS 需要新的域名、DNS 和 ACME 条件，不能在升级中安全猜测。在线更新原先还会在 root 任务中重新查询最新 Release，使页面排队目标可能与实际安装版本不同。

## 决策

- 全新安装默认选择独立域名的 Let’s Encrypt HTTPS；HTTP 只保留为管理员显式选择。
- 受管升级继续从现有 root-owned `panel.env` 读取并原样保留面板协议，不做静默迁移。
- 面板协议、面板证书与 Hysteria 数据通道身份完全分离；本决定不修改节点域名、端口、用户 URI、token、HMAC、Hysteria 证书或固定指纹。
- 在线更新服务读取面板排队状态中的严格 `vX.Y.Z` 目标，并只下载、验签和执行该版本；手工 root CLI 未指定排队目标时仍可检查最新正式版本。
- 排队状态读取拒绝符号链接、非普通文件、多硬链接、非 `0600` 权限或与状态目录属主不一致的文件；校验和读取使用同一文件描述符完成。
- 已存在状态文件时，只有 systemd 明确报告更新单元为 `inactive` 或 `failed` 且没有待执行 Job，才允许建立下一任务；其他状态和无法核验状态均拒绝覆盖。受支持入口是单一面板进程中的更新操作，手工直接启动 root 更新单元不属于受支持工作流。
- Release API 检查保持单次有界请求，超时由 3 秒放宽到 10 秒。

## 后果

- 新部署必须为面板准备独立 DNS 和可达的 TCP 80/19998，换取默认传输保密性。
- 历史 HTTP 安装不会因普通在线升级失去管理面访问；运营方可在维护窗口显式迁移。
- 更新页面、审计目标和实际安装版本保持一致；执行期间发布的新版本留到下一次检查和更新。

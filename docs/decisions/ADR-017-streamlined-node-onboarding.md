# ADR-017：以持久完成器收敛数据节点对接流程

## 状态

已接受

## 日期

2026-08-28

## 背景

现有安全流程把节点注册、Ed25519 指纹核对、心跳启用、协议启用、数据面 bootstrap、
真实灰度和 DNS 准入拆成独立人工步骤。每一步本身安全，但重复复制命令容易遗漏，
也会让服务器迁移显得比实际复杂。

用户端配置是不可变边界：自动化不得改变 Hysteria 公网域名、UDP 端口、用户 token、
HMAC、分享 URI、长期证书或固定指纹。DNS 和云安全组也不应要求面板持有第三方高权限
凭据。

## 决定

全新节点的签名安装命令在完成注册后安装一个 root-only、固定版本的 systemd 完成器。
完成器只会执行仓库内固定的 onboarding 子命令，并周期性进行下列状态转换：

1. 指纹尚未由管理员确认时保持等待，不安装 Hysteria；
2. 确认后用节点 Ed25519 私钥发送心跳和签名 bootstrap claim；
3. 面板确认节点身份、来源 IP 和在线状态后自动启用协议并返回短时节点绑定 grant；
4. 完成器复用既有事务部署 FULL、中央现有主 UDP 端口/443、fq/BBR 和 16 MiB UDP 缓冲；
5. 面板使用仅对该活动 grant 有效的保留身份完成公网直连灰度；
6. 用户手工增加 DNS 后，面板只读解析器在所有新鲜度门满足时自动记录准入。

claim 是固定 JSON 合同，不接受 shell、路径、URL、端口或任意命令。响应丢失后可重新
签发；新 grant 原子废止旧 grant，数据库始终只保存 token 摘要。若中央 ACK 后进程在
清理 timer 前中断，无数据面事务标记且六项服务、身份和四个监听全部健康时，完成器只
清理自身而不重复部署；若中断时事务仍存在，同一已验证节点可重新领取恢复 grant，先按
事务恢复再重装。完成器因此可跨 SSH 断线和重启重试，数据面失败继续使用已有事务回滚。

## 考虑过的方案

### 删除指纹确认

拒绝。注册 token 泄漏或网络路径被替换时会让伪造节点自动取得生产 Hysteria 身份。

### 把 bootstrap shell 作为控制命令下发

拒绝。即使中央可信，通用 shell 面也会把控制协议升级为 root 远程执行接口。固定
installer 子命令更易审计和回滚。

### 在面板保存 Cloudflare 或云厂商凭据

拒绝。会扩大秘密范围和第三方权限。DNS 继续由用户修改，面板只做精确、只读检测；
安全组由云平台设置，真实公网灰度负责发现遗漏。

### 使用真实用户做灰度

拒绝。会污染设备数、在线数和流量，并可能让运维依赖某个用户。保留身份只绑定活动
bootstrap grant，ACK 后立即失效。

## 后果

- 正常新增节点缩短为一条命令、一次指纹确认、一次 DNS 操作。
- 指纹确认仍是唯一不可自动化的节点信任门。
- DNS 解析或控制状态暂时不新鲜时只延迟准入，不会自动回滚或删除用户 DNS。
- 第三方网络故障会使真实灰度失败并触发现有数据面回滚；不会误报节点可用。
- 已有节点重绑定继续保留私钥、Hysteria 身份和 traffic spool，默认不自动重写运行中
  的数据面。

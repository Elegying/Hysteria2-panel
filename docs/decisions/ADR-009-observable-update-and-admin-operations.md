# ADR-009：可观测在线更新与受限运维操作

- 状态：已接受
- 日期：2026-08-12

## 背景

旧版在线更新只确认 systemd 接受了启动请求，页面随后显示静态提示。更新任务实际失败、面板重启期间短暂断开或安装完成后版本未变化时，管理员都得不到可靠反馈。用户限额也只能在创建时设置，降低设备上限后的存量在线实例缺少明显告警。

## 决策

1. 更新排队时把目标版本与状态原子写入 `/var/lib/hysteria2-panel/update-status.json`，权限为 `0600`。
2. 增加认证后的状态查询接口，结合固定更新单元的 `ActiveState`、`SubState`、`Result`、退出码和当前面板版本返回排队、运行、成功或失败。
3. 浏览器异步提交更新并在面板重启期间容忍短暂网络错误；只有当前版本达到目标版本才宣告成功。
4. 用户限额编辑采用 CSRF、范围校验和 `generation` 乐观锁，只修改设备与总流量限制，不改变 token、累计流量或分享 URI。
5. `/online` 继续作为 Hysteria 客户端实例估算；不使用来源 IP 或端口伪装成硬件指纹。超过配置上限时用颜色和文字双重告警。
6. 整机重启只允许管理员通过固定的 `systemctl --no-block reboot` 白名单调用，不接受浏览器提供命令参数。
7. 在线更新单元允许 `AF_NETLINK` 读取网卡地址；安装器把公网地址探测视为非关键步骤，已有安装始终优先使用持久配置，探测失败不得阻断升级。

## 结果

更新失败可在页面上诊断，更新时的预期重启不再表现为无响应。限额维护不会破坏已经发放的节点链接。整机重启被纳入面板审计和固定命令边界，但 HTTP 面板仍应限制管理端口来源；CSRF 不能替代传输加密或网络访问控制。

物理设备级授权仍不属于标准 Hysteria 2 服务端能够可靠提供的能力。若未来引入受控客户端和逐设备凭据，需要单独设计兼容与迁移方案，不能静默改变现有链接语义。

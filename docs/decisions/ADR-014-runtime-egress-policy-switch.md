# ADR-014：面板内受限切换节点全局出站策略

## 状态

已接受，适用于 v0.21.0 及以后版本；取代 ADR-006 中“只能重新运行安装器切换策略”“`full` 不写 ACL”和“缺省为 `web`”的具体决定，保留其端口白名单不是 DPI 的风险结论。

## 日期

2026-08-20

## 背景

不同节点的用途和滥用风险不同：高用户量节点通常需要 `web` 白名单，少量可信用户节点可能需要游戏、开发或其他公网非标准端口。要求管理员每次通过 SSH 重跑安装器容易误操作，也无法在面板中直接看出当前策略。与此同时，面板进程使用非 root 身份，不能获得写任意 Hysteria 配置或执行任意命令的能力。

## 决策

- 在服务端口卡片显示持久化的 `FULL` 状态，并提供节点级开启/关闭按钮；它作用于全部账号，不进入用户数据库、备份或分享 URI。
- 管理路由只接受路径中严格匹配的 `web` 或 `full`，继续要求有效管理会话和 CSRF token。两种目标分别映射到参数固定的 systemd oneshot 和精确 sudoers 条目，不使用 shell，也不接受客户端命令、路径、端口或 ACL 文本。
- root 任务与安装、更新和恢复共用排他维护锁。它只接受 root 所有、单链接、非符号链接且不可组写/全局写的固定受管文件，生成项目内置 ACL，并通过同目录临时文件、`fsync` 和 `os.replace` 更新主入口、UDP `443` 入口与 `panel.env`。
- `web` 和 `full` 都先拒绝未指定、环回、私网、CGNAT、链路本地、IPv6 ULA、组播和保留地址；`web` 再放行固定网页/运维端口并最终拒绝，`full` 放行其余公网目标和全部端口。
- 更新前记录主 Hysteria unit 是否运行；运行中的节点重启主 unit 并同时复核可选 UDP `443` unit，已停止的节点保持停止。任一写入、重启或复核失败时恢复三份原文件和切换前服务状态；无法完成回滚时任务保持失败并要求人工处理。

## 备选方案

### 让面板直接编辑 YAML 或通过 sudo 运行带参数脚本

浏览器输入会跨越到 root 文件或命令边界，扩大命令注入、路径替换和配置破坏风险，因此拒绝。

### 只改环境变量，等待下次部署再生成配置

状态显示会与实际 ACL 不一致，且管理员无法确认切换何时生效，因此拒绝。

### 按账号选择 `full`

Hysteria 当前 ACL 是进程级出口策略；实现账号级差异需要拆分更多 Hysteria 实例或引入新的流量分类层，明显增加端口、统计和故障面，不属于本次范围。

## 结果

- 管理员可在一个明确位置查看和切换真实持久策略，不再需要 SSH 重跑安装器。
- 切换会短暂中断全部 Hysteria 连接；界面必须在提交前说明这一点，并在开启 `full` 时提示 BT/PT、邮件滥发、扫描和投诉风险。
- 同一时刻只允许一个受管维护任务修改配置。极端掉电仍可能发生在多个原子替换之间，但旧文件保存在进程内用于普通失败回滚，安装器升级前也会继续创建完整 `/etc` 备份；生产切换后必须复核两份 ACL、systemd 和真实数据面。

# ADR-018：按入口机器归属设备数与用户流量

## 状态

已接受

## 日期

2026-08-29

## 背景

中央面板已经按用户汇总面板本机和数据节点的设备数与流量，用于统一执行设备上限和
流量额度，但仪表盘不能回答“这些设备和流量来自哪台服务器”。服务器更换、节点流量
耗尽或故障排查时，只有全局合计不够直观。

现有用户 URI、token、域名、端口和固定证书指纹是不可变兼容边界。分机器统计不能让
用户先连接面板再跳转，也不能为了采集硬件标识改变标准 Hysteria 客户端协议。

## 决定

数据库新增稳定的流量来源和来源-用户累计表。面板本机使用安装器生成并在升级中保留的
随机来源 ID；数据节点直接使用已验证的稳定 `node_id`。本机统计批次和签名节点统计批次
在更新用户总量的同一 SQLite 事务内更新来源明细，继续复用原批次账本实现幂等。单用户
重置、全量重置、用户删除以及事务回滚同时作用于总量和来源明细。

升级前已经存在的累计流量无法可靠反推到具体机器，因此只迁移到“升级前历史（未归属）”
来源，且只执行一次。任何时候都维持以下不变量：

`所有当前来源流量 + 升级前未归属流量 = 用户累计总流量`

在线设备继续来自 Hysteria `/online`：本机读取实时值，数据节点读取带签名的在线快照。
只有通过与中央鉴权相同新鲜度门的节点才计入当前合计。过期快照保留“上次值”用于排障，
但不冒充当前在线；仪表盘明确标记当前设备合计不完整。

备份继续携带整个 SQLite 数据库，因此会原样保留历史来源。`panel.env` 不属于用户备份的
替换范围：新服务器先由一键安装器生成新的本机来源 ID，恢复旧数据库后旧本机记录成为
历史，新服务器从新的来源继续累计。这样不会把两台物理服务器误合并。

## 考虑过的方案

### 从云厂商网卡或系统接口读取流量

拒绝。它包含面板、更新、探针和其他系统流量，与 Hysteria 用户额度不是同一口径，也
无法稳定按用户拆分。

### 把面板本机伪装成 `nodes` 表中的数据节点

拒绝。`nodes` 参与协议就绪和全局新鲜度门，伪节点会污染中央认证并可能导致全部新认证
失败关闭。

### 把升级前流量全部归给当前面板本机

拒绝。历史流量可能来自多个数据节点，这会制造不可验证的错误归属。

### 用 IP、端口或硬件指纹统计物理设备

拒绝。标准 Hysteria 认证没有稳定硬件 ID；NAT、移动网络和重连都会产生误判。设备数仍
明确表示同时在线的 Hysteria 客户端实例。

## 后果

- 面板可以同时展示全局合计、卡片中的主要机器拆分和完整节点统计表。
- 节点快照过期时设备合计宁可标为不完整，也不把上次值当作当前值。
- 新增统计不改变任何用户连接配置、数据路径或中央鉴权协议。
- 节点重绑定复用同一 `node_id` 时延续历史；明确创建新身份时从新来源开始累计。
- 面板显示的是 Hysteria 已结算用户流量，不保证等于云厂商或 NIC 的计费字节数。

# ADR-026：认证重试与当前权限复核

- 状态：已接受
- 日期：2026-10-10

## 背景

本机认证先查 token 与入口权限，再等待统计采样和设备名额预留。用户在等待期间关闭 UDP `443` 权限时，早先的查询结果可能过时。

节点认证按 `(nodeId, requestId)` 保存短期决策，避免重试重复占用设备数。原实现命中允许决策时只检查安全清退命令，绕过了当前凭据、入口权限、用量和全局快照检查。清退完成后，旧凭据还可能借原请求编号重新获得允许；旧初始化授权也可能在重新签发后复用其先前决策。

## 决定

1. 本机认证把入口要求传递到现有设备预留事务，与启用、清退和额度条件一起复核。主入口保持原有语义，拒绝的 UDP `443` 请求不产生新租约。
2. 节点重试复用现有身份、权限、全局新鲜度和容量校验路径，随后才返回原决策。仍须通过签名、来源和新 nonce 校验，不接受原签名请求的重复 nonce。
3. 当前凭据必须仍有效且属于原决策账号；入口权限、流量额度和设备限制继续生效，自动验收凭据必须仍有有效的初始化授权。
4. 已允许的同账号重试承认原有的一个容量预留，不再要求第二个空位。设备限制调低导致现有占用超限时拒绝重试。
5. 保持原决策编号与到期时间，不新增记录、不续期，也不提前释放可能已被在途连接使用的原预留。原拒绝结果不会在同一请求编号下升级为允许；策略放宽后应使用新请求。

## 后果与边界

- 不增加数据库表、存储凭据或协议字段，已有 token、URI 和请求结构保持兼容。
- 幂等性保证决策身份与预留不重复，不能保证被撤销权限对应的旧允许结果永久不变；当前安全状态优先。
- 快照过期按现有协议失败关闭；其他当前准入条件不满足时返回拒绝决策。
- 本机回归通过真实回环 HTTP、管理接口、并发等待和 SQLite 验证。节点回归执行中央协议服务及 SQLite 事务，签名校验和本机状态提供器使用隔离测试替身。
- 此规则管理新的认证决策。已经提交并发出的允许响应、已建立的 QUIC 连接及清退完成证明继续遵循已有传输时限和清退流程，不能仅凭本次回归声称所有旧连接立即消失。

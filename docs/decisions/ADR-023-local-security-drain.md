# ADR 023 本机改密后的持久化清退

状态：已实现，待真实 Linux 数据面验收。

## 问题

继续审查发现，Web 与 App 改密调用本机 `/kick` 后就返回；后续采集只清退禁用、删除或超额账号。改密后账号仍启用且未超额，因此三条旧连接只关闭一条，另外两条可以继续传输。

## 决策

在 `proxy_users` 增加可空列 `local_drain_started_at`。现有数据库初始化沿用增量迁移补齐，旧用户默认没有待清退任务。Web 与 App 改密在取得 SQLite 写事务后，把新密钥、代际递增和清退开始时间一起提交；普通身份层的令牌轮换调用保留原接口行为。

本机认证事务在清退标记存在时暂缓该账号的新认证；账号本身仍启用，其他账号和远端节点继续使用各自的授权规则。定时采集按主入口和 UDP `443` 的合并在线列表持续清退目标账号，初次统计接口失败或面板重启都不会丢失任务。

只有目标账号在所有本机入口均离线，且改密时间已过去至少 11 个整数秒，才能清除标记。该时长覆盖上游 10 秒 HTTP 认证超时以及整秒时间戳的取整误差；上游实现参见[固定版本 HTTP 认证器](https://github.com/apernet/hysteria/blob/14e9fff1d972ab0187ac7fcf75b9514dc8664065/extras/auth/http.go#L16-L18)。清除使用用户 ID、代际与开始时间比较，防止旧观察误清除同一秒发生的第二次改密。

## 兼容与验证

不回滚已经生成的新密钥，也不会在初次清退失败时隐藏连接信息。新认证的短暂拒绝是排空期间的状态；空闲旧连接仍依赖后续流量事件消费上游清退标记。操作完成条件是实际连接清空，不是 `/kick` 请求成功。

回归覆盖真实 Web/App 改密 HTTP、三条连接、其他账号隔离、初次清退失败、面板对象与数据库重建、在途认证窗口、同秒再次改密及旧数据库迁移。实际双入口 QUIC 行为仍需 Linux 节点验收。

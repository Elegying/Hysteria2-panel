# ADR-007：固定来源的非交互在线更新

## 状态

已接受，适用于 v0.12.0 及以后版本。

## 背景

旧面板只能查询 GitHub 最新版本并显示发布链接，没有执行更新的后端、系统服务或非交互安装模式。让浏览器直接提供版本、URL 或 shell 命令会把面板账号提升为任意 root 代码执行入口；直接运行默认交互安装器又会卡在终端输入，并可能意外改动已经分享的节点身份。

## 决策

- 管理面板新增 `POST /updates/apply`，继续要求有效会话和 CSRF，但请求体不接受版本、URL、命令或部署参数。
- 面板用户只能通过精确 sudoers 白名单启动固定的 `hysteria2-panel-update.service`；一次性任务以 root 运行项目内的 `apply-update` 子命令。
- root 更新器重新查询固定仓库的 GitHub `releases/latest`，只接受比当前版本新的严格 `vX.Y.Z` tag，并只从该 tag 的固定 raw GitHub 路径下载 `install.sh`。
- 执行前限制远程内容大小，验证 UTF-8、bash 解释器头、安装器内嵌版本与 release tag 一致，并执行 `bash -n`。
- 更新器使用最小固定环境启动安装器的 `HY2PANEL_AUTO_UPDATE=1` 模式。该模式只允许现有受管安装，强制沿用现有节点、端口、面板协议、出站策略和内部端口，并禁止重置管理员。
- 安装器原有的一致性数据库备份、目录备份、固定源码 SHA-256 校验、服务重启和健康检查继续作为实际升级门禁。

## 取舍

### 从浏览器提交版本或下载地址

灵活但扩大 root 输入面，容易形成命令注入、SSRF 或降级安装，因此拒绝。

### 自动执行任意主分支脚本

无法把用户可见的正式发布与待开发代码分开，也没有稳定版本语义，因此拒绝。

### 在面板进程内直接覆盖文件

面板以非 root 用户运行且有文件系统沙箱。放宽该长期进程的权限会扩大攻击面，因此拒绝；只授权启动短生命周期、固定命令的一次性任务。

## 结果

- 管理员可在面板内完成正式版本升级，不需要再次输入部署参数。
- 更新期间面板和 Hysteria 会短暂重启；安装器的升级前备份保存在 `/var/backups/hysteria2-panel/`。
- GitHub 仓库与正式 release 仍属于供应链信任根。若无法访问固定 API/下载地址，或安装器校验失败，更新任务会失败关闭并在 systemd 日志中留下原因，不会改用镜像或不受信地址。

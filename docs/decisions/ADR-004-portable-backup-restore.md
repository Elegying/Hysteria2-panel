# ADR-004：可迁移用户身份与原子恢复

## 状态

已接受，2026-08-10。

## 背景

用户会频繁更换服务器。只复制 SQLite 不能恢复新式用户 token，因为 token 由随机种子和独立 HMAC key 派生；只复制证书指纹也不能让服务端证明原 TLS 身份，因为必须同时拥有原证书和私钥。旧客户端 URI 还固定了公网地址、UDP 端口和叶子证书 SHA-256，任一项变化都会破坏无感迁移。

面板以非 root 用户运行，不能直接替换 `/etc/hysteria2-panel` 下的签名环境、证书和私钥。上传 ZIP 又属于高风险输入，不能让 Web 进程解压任意路径或获得通用 root 权限。

## 决策

- 格式版本 1 的 ZIP 固定包含 `manifest.json`、一致性 SQLite 快照、HMAC key、TLS 证书和 TLS 私钥。SQLite 快照只保留代理用户行，清除旧管理员、会话和审计记录；清单记录源域名、UDP 端口、节点名、证书指纹/有效期、用户数和每个文件的大小/SHA-256。
- 恢复只替换 `proxy_users`，保留目标服务器当前管理员、审计历史和部署专用统计 secret；恢复前清空全部管理会话。这样新服务器的登录账号不会被旧备份意外覆盖。
- 恢复必须同时验证 ZIP 结构与大小、文件校验和、SQLite 完整性和表结构、签名 key 与所有带 seed 用户 token 的一致性、证书/私钥配对、清单指纹，以及源/目标公网域名与 UDP 端口完全一致。
- 替换完成后必须从最终磁盘路径逐列比较全部代理用户行，并再次验证 SQLite、HMAC、证书/私钥、指纹、有效期和用户数量；二次校验属于原子恢复事务的一部分，失败时恢复数据库、证书、私钥和环境文件。
- Web 进程只在同一维护锁文件取得短暂只读共享准入后，把预检 ZIP 原子写入固定待恢复路径；root 安装、更新或恢复持排他锁时拒绝新上传。Web 进程随后通过 sudoers 中唯一的固定命令异步启动 `hysteria2-panel-restore.service`，不能指定路径或命令。
- root oneshot 与安装/更新共用阻塞维护锁；取得锁后先停止面板写入但保留实际运行的 Hysteria 统计端点，清退在线连接、结算流量并完成 SQLite checkpoint，随后才停止其余服务、重复校验、建立已 `fsync` 的当前身份自动备份并以临时文件替换数据。
- 恢复事务使用 `/etc/hysteria2-panel/.restore-active` 的 root `0600` 版本化 JSON 标记，阶段依次为 `queued`、`prepared`、`disk-consistent` 和 `services-pending`。标记只记录受限路径、摘要、阶段和结果，不保存秘密；归档、备份、每次文件替换、SQLite WAL/SHM 清理以及标记更新都在进入下一阶段前同步文件和父目录。无效、可写、越界或符号链接路径一律安全停止。
- 静态的 `hysteria2-panel-restore-recover.service` 是面板和 Hysteria 启动前的强依赖，只做文件事务收口：完整验证最终身份，或从自动备份恢复数据库、证书、私钥和环境文件，清除 WAL/SHM，再把阶段推进到 `services-pending`；它不启动服务，也不删除标记。前置恢复失败会阻止业务服务启动，避免暴露混合身份。
- 服务正常启动后，`hysteria2-panel-restore-resume.service` 才连续两轮验证所需 systemd unit、面板/认证健康接口、实际统计端点和 TCP 探测。此阶段不再用会随正常流量变化的完整数据库哈希复核；只有启动前身份已经验证且运行健康才删除事务标记。进程、信号或重启中断时，两阶段从持久标记幂等继续。
- root 恢复失败或发现没有有效事务标记的 pending/captured orphan 时，把归档安全复制或改名隔离为权限 `0600` 的失败样本，持久化目录更新并释放固定待恢复路径，让管理员可以直接重试而不需要 SSH 删除文件。root 端通过 `O_NOFOLLOW`、同一文件描述符的所有权/模式/链接数检查和摘要复核抵御符号链接与替换竞态。
- 安装器升级和恢复默认复用证书，不自动续签、重签或轮换。任何产生新叶子证书的操作都会改变 `pinSHA256`，必须重新分享节点。

## 备选方案

### 只备份 SQLite

缺少 HMAC key 时，恢复后的 token 指纹和由 seed 重建的 token 都不匹配，因此拒绝。

### 只记录证书指纹

指纹不是服务器私钥，无法恢复 TLS 身份，因此拒绝。必须备份证书和私钥。

### 恢复源服务器全部环境文件

会覆盖目标面板端口、协议、统计 secret 和管理员部署选择，迁移到新主机时风险过高，因此只更新 HMAC key 与证书 pin。

### 给面板 `/etc` 写权限或通用 sudo

会把文件上传漏洞扩大为主机控制权限，因此拒绝。采用固定路径、固定 unit 和 root 端二次校验。

### 域名或端口不一致时仍强制恢复

数据可以复制，但旧客户端仍会连接旧地址，无法满足“恢复后原节点可用”的目标，因此默认拒绝并要求以相同域名/端口重新部署。

## 后果

- 同域名、同 UDP 端口迁移时，更新 DNS 后旧客户端无需重新导入；直接使用旧 IP 或改变端口时不能无感迁移。
- ZIP 含全部代理凭据和 TLS 私钥，必须视为高敏感秘密；HTTP 面板上的下载/上传没有传输层保密性。
- root 恢复会短暂停机，并在成功后使全部旧管理会话失效；目标面板管理员继续有效。
- 跨服务器切换必须先在新服务器通过 IP 面板完成恢复和校验，再切换 DNS；提前把流量导向未恢复的主机会造成旧 token 暂时认证失败。
- 证书续签或轮换不是普通恢复操作，必须计划重新分享新指纹。

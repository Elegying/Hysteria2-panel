# ADR-024：异地备份与计量进程隔离

- 状态：已接受
- 日期：2026-10-10

## 背景

每日异地备份以 root 运行，原来在归档前另建 `UsageManager` 清零并结算本机流量。面板进程仍然存活，两者拥有独立的内存批次，却共用同一个 `pending-traffic.json`。故障重试时，一个进程可能删除另一个进程刚写入的批次；另一个进程结束后，该批流量没有剩余的持久化依据。

备份 systemd 单元还把本机代理列为强制启动依赖，因此定时任务可能恢复管理员已经停止的代理，即使异地目标尚未配置。

## 决定

1. 每日异地任务只使用既有 `BackupManager` 和 SQLite 在线备份 API，归档已经提交的用户与身份数据。
2. 日常破坏性统计读取和待入账日志继续由面板的采集进程拥有，异地任务不创建第二个采集器，不消费或清除重试日志。
3. 异地备份保留面板服务依赖和现有启动顺序，但不通过启动依赖拉起任一代理入口。统计接口停止不妨碍备份已提交数据库。
4. 网页手动备份继续在面板自身的 `UsageManager` 锁内先结算再归档；升级、恢复和出站切换的既有维护结算流程不变。

## 后果

- 每日备份代表 SQLite 已提交状态的一个一致快照，可能不含尚未采样或仍在重试日志中的流量；这些记录继续留在原采集路径，提交后进入后续备份。
- 保留现有备份格式、用户身份、在线 SQLite 快照与归档自校验，不增加 root 控制接口、额外的常驻采集进程或两进程日志交接协议。
- 回归执行实际 `offsite-backup` CLI 工厂、SQLite 归档和失败后重试，核对没有额外清零或日志修改。安装器依赖契约和 Linux systemd 探针约束停服状态；本地 macOS 不代表 Linux 探针已经执行。

# 稳定化与发布质量

本项目把可靠性、安全边界和可恢复性放在功能数量之前。本文定义当前长期适用的合并与发布底线，不再绑定某个旧版本号。

## 变更分级

| 类型 | 示例 | 要求 |
|---|---|---|
| 缺陷与安全修复 | 认证、流量、恢复、权限、兼容性问题 | 必须有能复现旧问题并证明修复的回归测试 |
| 文档与可观测性 | 操作说明、指标、日志、错误提示 | 不得泄露身份或扩大接口；命令和链接需要验证 |
| 内部重构 | 模块拆分、重复逻辑整理 | 对外行为、安装哈希清单和兼容路径保持不变 |
| 功能变化 | 新入口、新协议字段、新持久身份 | 先写规格或 ADR，说明迁移、回滚、安全和 E2E |
| 破坏性变化 | 改 URI、证书、数据库或备份格式 | 默认不接受；确需实施时必须提供完整迁移和旧版本兼容计划 |

## 合并门禁

每个 PR 根据影响范围通过以下检查：

- Python 3.8、3.12、3.13 单元与集成测试；
- Python 3.13 `ResourceWarning` 连接泄漏回归；
- Ruff、Bandit、ShellCheck、shell/Python 语法；
- 当前树和新增历史的敏感信息与退役基础设施扫描；
- 真实 Chrome 桌面与手机视口 smoke；
- UFW、firewalld 与 RHEL 包管理契约；
- systemd 服务与 watchdog 语义；
- 完整安装、升级和异常中断恢复 E2E。

受保护 `main` 当前要求九项 GitHub 状态检查，严格绑定最新基线；没有绕过者。仓库设置可能变化，发布前仍必须通过 GitHub API 重新读取，而不能只依赖这份文档。

## 关键回归场景

以下路径发生变化时，测试必须直接覆盖对应行为：

- 中央不可达时，数据节点流量先进入 durable spool；
- 其他健康节点继续结算，不被单节点故障阻塞；
- 中央恢复后精确重放，重复批次不重复累计；
- 升级或恢复被强制终止、进程重启、主机重启后可以继续或回滚；
- 用户 URI、token 派生、Hysteria 证书、节点 Ed25519 身份和 spool 保持；
- 主入口与 UDP `443` 分别完成真实 Hysteria 数据面验收；
- 页面在桌面和手机无横向溢出，关键操作可用键盘完成，弹窗焦点可以恢复。

## 正式发布判定

正式版本必须同时满足：

1. 候选提交是最新受保护 `main`；
2. 版本源码、安装器、变更日志和标签一致；
3. 标签 push 的全部常规 CI 通过；
4. Ubuntu、Debian、Rocky Linux 的 amd64/arm64 六平台安装矩阵通过；
5. Release 先保持草稿，安装器和 SBOM 均完成 Sigstore 签名、重新下载、逐字节比较和验签；
6. 发布工作流最后一步才把草稿改为公开；
7. canary 节点完成真实客户端握手、流量、重启和必要的回滚演练；
8. 多节点遵循 `max-unavailable=1`，任何时刻只升级一台。

发布前应保证候选版本至少连续 48 小时没有新增 P0/P1，并在真实浏览器抽查键盘路径、200% 缩放和屏幕阅读器。截图与自动化 smoke 不能单独证明 WCAG 合规。

## 失败处理

出现失败时先保存证据：

- systemd 状态与 journal；
- SQLite、WAL/SHM 状态；
- 节点 spool；
- 安装、更新或恢复事务标记；
- 最近自动备份及其清单；
- 精确提交、标签、Actions run 和 job 集合。

不要通过反复运行、删除标记、清空 spool 或只复制数据库来制造“绿色”结果。确认属于测试环境抖动时，应先增加可复现证据和有界超时解释，再调整门禁。

生产滚动升级中，任何节点的身份、健康、流量、监听或真实 Hysteria 握手失败，都必须立即停止后续批次，并按[发布与回滚](DEPLOYMENT.md)处理。
